01 / Executive assessment

An exact decimal boundary — and a dependency decision

fast_float is a header-only C++ library implementing from_chars-style numeric text conversion for float, double, and integers. It avoids dynamic allocations and exceptions inside the conversion routine, does not use the process locale, and targets correct nearest-even binary rounding. It supports C++11 onward; this edition focuses on C++20.

Worth evaluating

Input of bounded decimals

Telemetry logs, deterministic replay traces, CSV-style measurements, numerical test vectors and device responses.

Benchmark first

Standard from_chars exists

GCC's library already vendors fast_float for relevant conversions. A separate library may offer little improvement over your target standard library.

Recommendation: start with an allocation-audited parsing façade, compare std::from_chars against fast_float on the actual target, and only add the dependency for a verified benefit or required grammar.
02 / Problem

A decimal string is not a floating-point value

In a text trace, -12.5,0.003,1e2 comprises fifteen ASCII bytes. Before it is meaningful simulation data, software must recognize three tokens, handle exponent notation, choose binary values, validate separators, reject invalid numbers and ensure no extra characters remain.

Most decimal fractions are not exactly representable in a binary double: the familiar 0.1 is an approximation. Correct conversion chooses the nearest binary value, resolving exact midpoints with ties-to-even. A naive multiply-and-divide conversion can be inaccurate; the upstream library builds on specialized conversion algorithms and research.

Its pointer-and-length API is attractive for allocation-free systems: read directly from a bounded slice [first,last), without constructing a zero-terminated copy. However, nonallocating conversion is not proof of a nonallocating entire application or bounded worst-case execution time.

03 / Semantics

The cursor is as important as the number

The documented result includes ptr (where parsing stopped) and ec (an error code). Successful recognition of a prefix is not equivalent to validation of a whole record. The default format rejects leading whitespace and a leading plus sign. The caller must check r.ptr == end when the whole field must be numeric.

05 / Working pattern

A strict three-value telemetry record

This C++20 example does whole-record validation: no dynamic strings, no allocations in the parser, exactly three comma-separated finite doubles, no stray suffixes, and no partial publication. The scratch array prevents an out-of-range or malformed later field from corrupting a previously valid output record.

// main.cpp — C++20
#include <array>
#include <cmath>
#include <cstddef>
#include <string_view>
#include <system_error>
#include "fast_float/fast_float.h"

// Three finite comma-separated numbers; failure leaves out unchanged.
// Fixed local array, no dynamic strings or allocations in this function.
[[nodiscard]] bool parse_triplet(std::string_view wire,
                                 std::array<double, 3>& out) noexcept {
  if (wire.empty()) return false;
  const char* cursor = wire.data();
  const char* const end = cursor + wire.size();
  std::array<double, 3> candidate{};

  for (std::size_t i = 0; i < candidate.size(); ++i) {
    if (cursor == end) return false;
    const auto r = fast_float::from_chars(cursor, end, candidate[i]);
    if (r.ec != std::errc{} || r.ptr == cursor ||
        !std::isfinite(candidate[i])) return false;
    cursor = r.ptr;
    if (i + 1 < candidate.size()) {
      if (cursor == end || *cursor != ',') return false;
      ++cursor;
    }
  }
  if (cursor != end) return false; // reject trailing bytes
  out = candidate;                // atomic publish after full check
  return true;
}

int main() {
  std::array<double, 3> out{99, 99, 99};
  if (!parse_triplet("-12.5,0.003,1e2", out)) return 1;
  if (out != std::array<double, 3>{-12.5, 0.003, 100.0}) return 2;
  const auto baseline = out;
  for (const char* bad : {"1,2,3junk", "+1,2,3", "nan,2,3",
                          "1e9999,2,3", "1,2"}) {
    if (parse_triplet(bad, out) || out != baseline) return 3;
  }
  return 0;
}

Review and verification: uses the v8.3.3 documented fast_float::from_chars API. The same ordinary C++20 sample compiled and ran successfully against a temporary std::from_chars API substitute using GCC 14.2, with warnings treated as errors. That is not a compilation against fast_float v8.3.3 itself.

07 / Integration

Pin the release in CMake / Ninja

The upstream CMakeLists.txt declares an interface target FastFloat::fast_float and options FASTFLOAT_TEST and FASTFLOAT_BENCHMARKS. Pin a tag rather than tracking the default branch. The latest release checked here was v8.3.3, published October 31, 2026. Release notes · Build target definition

cmake_minimum_required(VERSION 3.24)
project(BoundedFloatParser LANGUAGES CXX)
include(FetchContent)
set(FASTFLOAT_TEST OFF CACHE BOOL "" FORCE)
set(FASTFLOAT_BENCHMARKS OFF CACHE BOOL "" FORCE)
FetchContent_Declare(fast_float
  GIT_REPOSITORY https://github.com/fastfloat/fast_float.git
  GIT_TAG v8.3.3
  GIT_SHALLOW TRUE)
FetchContent_MakeAvailable(fast_float)
add_executable(bounded_parser main.cpp)
target_compile_features(bounded_parser PRIVATE cxx_std_20)
target_link_libraries(bounded_parser PRIVATE FastFloat::fast_float)
include(CTest)
add_test(NAME bounded_parser_contract COMMAND bounded_parser)
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure

For mission-style reproducible builds, vendor the matching tag and record its exact commit SHA; remove build-time network dependence, keep license notices, and test under the target cross-compiler. The native CMake/Ninja target was not built in this run because the source was inaccessible to the local compiler environment.

08 / Real-time considerations

Allocation-free does not mean bounded WCET

Engineering propertyEvidence / limitation
Internal allocation and exceptionsUpstream documents neither heap allocation nor throws for conversion. Still inspect toolchain/runtime linkage.
Nearest-even conversionDocumented for ordinary float/double, under nearest rounding mode.
Fixed parser memoryDemonstration uses only stack-local std::array and caller-owned string_view. Upstream message length must itself be capped.
Worst-case timingNot established. Analyze slow paths and test pathological lengths/exponents on flight-like CPU.
Replay determinismCorrect conversion helps, but does not establish deterministic downstream floating arithmetic, FTZ/DAZ, ABI, compiler flags or scheduling.
Thread safetyParsing distinct caller-owned buffers/results avoids shared object state; caller must enforce buffer ownership and lifetime.

For RISCue, keep hard-deadline active-object queues in compact typed or binary form; parse ASCII at the ingress boundary, where length and deadline budgets can be controlled. Check that logging and error formatting do not allocate.

10 / Test and measurement

Acceptance criteria worth automating

The maintainers publish throughput approaching 1 GB/s on particular machines. That is their benchmark, not a local result and not a prediction for RISCue hardware. For a defensible decision, use identical corpora and checksums for native std::from_chars and fast_float, prevent dead-code elimination, and report throughput along with tail latency and code size.

Functional corpus

Zero/sign, halfway rounding, subnormals, extreme exponents, invalid leading signs, whitespace, suffixes, malformed exponent, nonfinites, and exact end-pointer position.

Boundedness corpus

Instrument new/malloc; cap input length; vary alignment and buffer lifetime; test worst-case strings; run sanitizers and fuzz malformed records.

Target evidence

GCC/Clang/MSVC or cross-compiler versions; CPU/ABI; FE_TONEAREST; FTZ/DAZ; -ffast-math policy; binary size; max/p99 latency.

Replay evidence

Compare bit patterns and replay hashes across targets, and ensure failure leaves all output state unchanged.

12 / Applicability

Project-specific hypotheses, not claimed deployments

RISCue

Parse bounded human-readable configuration or diagnostics outside tight active-object deadlines; deliver already typed values to queues.

VeloSim

Ingest ASCII trace vectors through a finite-only validated façade, then compare deterministic replay hashes across compilers.

BenchForge

Convert SCPI numeric responses from caller-owned buffers after verifying units, separators, CR/LF and instrument-specific error strings.

Native AOT C#

Use managed parsing baselines; consider native interop only if measured hot-path performance warrants the extra boundary.

Adoption gate: the strict parser plus baseline std::from_chars is useful immediately; importing the standalone library should be contingent on a concrete target benefit.
