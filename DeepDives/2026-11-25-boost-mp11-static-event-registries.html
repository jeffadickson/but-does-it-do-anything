Daily Library Deep Dive · 25 November 2026

Types are the registry.

Boost.Mp11 for statically checked event inventories, stable wire IDs and deterministic dispatch.

C++20 experiment · Boost 1.83.0 · BSL-1.0 · Host build and negative tests executed

Executive finding. A compile-time list can eliminate several classes of registry drift without runtime registration or dynamic allocation in the type algorithms. But an event's position in a type list must never become its protocol identity. The most valuable use is deriving and checking related artifacts from explicit metadata, not replacing every straightforward switch with templates.

01 · The engineering problem

A flight-style active object or a deterministic simulator has a finite event vocabulary. A handwritten enum, variant, decoder, dispatch table and test list can drift apart. Adding a new event may compile while an independent table silently omits it. Mp11 makes the type list a single input for deriving several of these artifacts. It does not replace the scheduler, message queue, protocol parser, or a requirements database.

Keep the authoritative protocol manifest under configuration control. A type list is a convenient representation of a design decision, not a substitute for a separately reviewed requirement. In particular, completeness is relative to the list: omission from the list itself remains possible.

Recommendation: Use Mp11 first for host-side test matrices and static event-registry validation; promote it to embedded target code after target compilation and memory-map review.

02 · The metaprogramming model

Mp11, maintained within Boost, works with variadic template instantiations as compile-time sequences. It can also accept compatible standard-library templates rather than requiring a bespoke container. The type operations themselves do not create runtime objects. Runtime bridge functions, however, can execute arbitrary user code. This distinction is fundamental for allocation and timing analysis. The API baseline here is Boost 1.83.0, matching the installed headers used for the experiment, not a claim that it is the latest release. See the versioned reference.

OperationEngineering use
mp_listClosed event type inventory
mp_transformExtract metadata as types
mp_uniqueCompare original and deduplicated counts
mp_findLocate a type; missing type returns the list size, not a negative value
mp_renameRebind the list to a variant or tuple
mp_productEnumerate combinations for test instantiation

Prefer explicit domain aliases and descriptive assertions over exposing a long nest of metaprogramming operations to every caller. Use mp_list for general transformations; a fixed-arity template such as std::pair cannot represent an arbitrary resized result.

03 · Stable identity versus list position

Use explicit protocol identifiers, not the ordinal in an Mp11 list or variant.index(). For example, Start is 0x0101 and Stop is 0x0205, independent of declaration order. A source reorder must not reinterpret an archived replay trace. An absent type is a compile-time sentinel in mp_find; guard before any index-based lookup. For external input, validate the runtime identifier and reject unsupported values before invoking a handler.

ChangeCorrect policy
Reorder listWire identifiers unchanged; internal variant ordinals may change.
Remove eventReserve old ID or use an explicit compatibility decoder.
Add eventReview reserved ranges, payload schema and protocol version.
Unknown IDReject, count or route to an explicit diagnostic path; never coerce to index zero.

Do not serialize a variant object, the table object or function pointers as raw bytes. ABI, padding, address layout and endianness are not a wire format. Production codecs need explicit field encoding, lengths, bounds, version and byte order.

04 · Complete tested C++20 example

This deliberately small example has payload-free events and a single owner of controller state. It checks uniqueness of both event types and stable IDs, derives a variant type for future mailbox storage, then generates a constant table of typed handler adapters. The example does not actually use the variant at runtime. The test uses return codes instead of assert so Release builds still exercise the checks.

registry.cpp · tested with actual Boost 1.83 headers

#include <boost/mp11.hpp>
#include <array>
#include <cstddef>
#include <cstdint>
#include <type_traits>
#include <variant>

namespace mp = boost::mp11;
struct Start { static constexpr std::uint16_t id = 0x101; };
struct Stop  { static constexpr std::uint16_t id = 0x205; };
struct Tick  { static constexpr std::uint16_t id = 0x310; };
struct Duplicate { static constexpr std::uint16_t id = Start::id; };
#ifdef DUPLICATE_ID
using Events = mp::mp_list<Start, Stop, Tick, Duplicate>;
#elif defined(DUPLICATE_TYPE)
using Events = mp::mp_list<Start, Stop, Tick, Start>;
#else
using Events = mp::mp_list<Start, Stop, Tick>;
#endif

template<class E> using Id = std::integral_constant<std::uint16_t, E::id>;
template<class L> constexpr bool unique =
    mp::mp_size<L>::value == mp::mp_size<mp::mp_unique<L>>::value;
static_assert(unique<Events>, "duplicate event type");
static_assert(unique<mp::mp_transform<Id, Events>>, "duplicate event ID");
static_assert(mp::mp_find<Events, int>::value == mp::mp_size<Events>::value);
using Event = mp::mp_rename<Events, std::variant>;
static_assert(std::is_trivially_copyable_v<Event>);

struct Controller {
    bool running = false;
    std::uint32_t ticks = 0;
    void on(Start) noexcept { running = true; }
    void on(Stop) noexcept { running = false; }
    void on(Tick) noexcept { if (running) ++ticks; } // unsigned wrap is intentional
};
struct Row {
    std::uint16_t id;
    void (*call)(Controller&) noexcept;
};
template<class... E>
constexpr auto make_table(mp::mp_list<E...>) {
    return std::array<Row, sizeof...(E)>{Row{E::id,
        +[](Controller& c) noexcept { c.on(E{}); }}...};
}
inline constexpr auto table = make_table(Events{});
bool dispatch(Controller& c, std::uint16_t id) noexcept {
    for (const auto& row : table) {
        if (row.id == id) { row.call(c); return true; }
    }
    return false;
}
int main() {
    Controller c;
    if (!dispatch(c, Tick::id) || c.ticks != 0) return 1;
    if (!dispatch(c, Start::id) || !c.running) return 2;
    if (!dispatch(c, Tick::id) || c.ticks != 1) return 3;
    if (dispatch(c, 0xffff) || !c.running || c.ticks != 1) return 4;
    if (!dispatch(c, Stop::id) || c.running) return 5;
    if (!dispatch(c, Tick::id) || c.ticks != 1) return 6;
    c.running = true; c.ticks = UINT32_MAX;
    if (!dispatch(c, Tick::id) || c.ticks != 0) return 7;
    return 0;
}

The maximum number of comparisons for this dispatcher is three. Unknown IDs leave the state untouched; a Tick while stopped does nothing. Unsigned tick rollover is intentionally defined modulo 232; real missions may require an explicit reject or saturate policy instead. The generated adapter default-constructs only empty event types in this example. For payload-bearing events, decode into an owned, validated payload first and pass it to the typed handler; default construction is not decoding.

The table is constant-initialized and has a static number of rows. The handler pointers still introduce an indirect call and may require relocations or RAM on a given target. An optimized switch or direct typed dispatch may be a better target implementation. Measure and inspect the actual target output.

05 · Runtime boundary and hidden work

mp_for_each bridges type sequences to actual function calls. Passing the original event type list can default-construct objects; that is dangerous if their constructors perform work or cannot be called. Wrap types in identities if you only need metadata. This illustrative fragment is source-reviewed, not part of the executed test:

mp::mp_for_each<mp::mp_transform<mp::mp_identity, Events>>(
    [](auto tag) {
        using E = typename decltype(tag)::type;
        static_assert(E::id != 0);
    });

The callback is ordinary C++ and may allocate, throw, access hardware or introduce nondeterminism. Likewise mp_with_index bridges a runtime index to a compile-time integral constant; validate the index against the nonempty list before calling it. Do not assume an out-of-range index is a recoverable error.

A type inventory can enforce trivial copyability and nothrow construction for known types, but those traits cannot prove that every handler, serializer or callback is allocation-free. A trivially copyable payload can contain a raw pointer with a problematic lifetime. A noexcept declaration also does not prove bounded time or that the implementation never calls a throwing function.

06 · CMake and Ninja integration

Use the exact installed Boost version for reproduction. No separately linked Mp11 library is needed. The tested CMake configuration uses the Boost umbrella header target; standalone Mp11 also supports subdirectory integration and its own package configuration according to the upstream README. For standalone use, vendor the reviewed revision, inspect its CMake target definitions, and retain its license. Do not download a moving branch during qualification.

CMakeLists.txt · tested

cmake_minimum_required(VERSION 3.20)
project(event_registry LANGUAGES CXX)
find_package(Boost 1.83.0 EXACT CONFIG REQUIRED)
add_executable(registry registry.cpp)
target_link_libraries(registry PRIVATE Boost::headers)
target_compile_features(registry PRIVATE cxx_std_20)
set_target_properties(registry PROPERTIES CXX_EXTENSIONS OFF)
if(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
  target_compile_options(registry PRIVATE -Wall -Wextra -Wpedantic -Werror -fno-exceptions -fno-rtti)
endif()
enable_testing()
add_test(NAME registry COMMAND registry)
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
# Each of the following is expected to fail at compile time:
g++ -std=c++20 -DDUPLICATE_ID -fsyntax-only registry.cpp
g++ -std=c++20 -DDUPLICATE_TYPE -fsyntax-only registry.cpp

For an embedded toolchain, supply a reviewed CMAKE_TOOLCHAIN_FILE, do not accidentally resolve host Boost headers from an unrelated SDK, and archive compiler version, flags, header hash, linker map and test outputs. For MSVC the example's GNU-style flags are not applied; an independent MSVC qualification run is required.

08 · RISCue, VeloSim and verification applications

RISCue and hierarchical state machines

Proposed: describe each active object's accepted events as a local list, derive a fixed message variant, check unique IDs and require explicit handlers. A closed event inventory does not establish HSM transition completeness, run-to-completion semantics, scheduling fairness, ISR safety or queue capacity. Keep those requirements and tests separate. Serialize queue producers according to the actual RTOS memory model; the dispatcher assumes single ownership.

VeloSim replay

Proposed: pair stable event IDs with versioned trace records and independently validate decode/dispatch. Equal ID mappings are necessary but insufficient for deterministic replay: order, timestamps, arithmetic policy and random seeds must also be controlled.

Host-side exhaustive type combinations

Use the type product to enumerate combinations of state and event types for test registration. A 20-state by 30-event model has 600 candidate pairs before configuration dimensions multiply it. Filter unreachable pairs only with a documented policy, not simply to make a build smaller. The following type-only illustration has not been separately compiled:

struct Idle;
struct Running;
using States = mp::mp_list<Idle, Running>;
template<class S, class E> using Case = mp::mp_list<S, E>;
using Cases = mp::mp_product<Case, States, Events>;
static_assert(mp::mp_size<Cases>::value ==
    mp::mp_size<States>::value * mp::mp_size<Events>::value);

For strongly typed C#/.NET Native AOT, the analogue is a build-time source generator plus analyzer rather than a direct port of Mp11. Generate stable identifiers and dispatch code from a reviewed declarative input; use an independent analyzer or test manifest to detect gaps. No C# implementation was attempted here.

09 · Verified adoption versus suggested use

Verified adoption: Boost.Variant2 actually includes Mp11. Inspection of the installed Boost 1.83 header boost/variant2/variant.hpp found the include at line 16, an mp_size use at line 144, and mp_at_c for alternative selection at line 165. These are concrete implementation dependencies, not just a library listing. See the matching upstream source path. This example also connects to the November 24 Deep Dive on Variant2.

Proposed only: RISCue, VeloSim and C# generator applications above. No repository integration, operational flight deployment, safety certification or third-party embedded adoption was established. The official Mp11 documentation describes generating type-combination tests; that is an upstream example, not evidence of specific external product deployment.

10 · Alternatives, costs and decision rules

ApproachBest whenTradeoff
Plain C++20 pack and foldsOne or two small transformsNo dependency; custom algorithms can accumulate and require review.
Mp11Repeated type-list algebra and generated test inventoriesTemplate instantiation cost, dependency pinning and unfamiliar diagnostics.
X-macrosSmall C-compatible registryPreprocessor limitations and weaker type-level composition.
External generatorCross-language protocol and requirements manifestsGenerator determinism, tool qualification and build dependencies.
Handwritten switchSmall target dispatch with straightforward reviewSeparate inventories may drift; compiler optimization is target-specific.

Estimate compile cost before creating large products or power sets. A power set of N distinct types contains 2N subsets; the fact that no runtime enumeration is needed does not make compilation or debug information cheap. Measure clean and incremental builds and object sizes on representative inventories. Cap accepted registry size as a design requirement. Avoid public APIs that expose excessive metaprogramming complexity.
