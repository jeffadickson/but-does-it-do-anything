00 / Executive assessment

Strong pilot candidate, not an RTOS drop-in verdict

Best first fitHost-side engineering models and RISCue HAL interfaces
Primary gainWrong units and wrong quantity kinds become compile errors
Main gateCross-toolchain, freestanding, object size, ABI and WCET verification

Most code reviews catch a type mismatch. Fewer catch the perfectly legal mistake of adding a sample period in milliseconds to a distance in metres, or treating two joule-valued quantities as interchangeable. mp-units moves those checks into the compiler instead of relying on naming conventions. The upstream project presents it as a C++29 standardization candidate, not an adopted C++ standard library facility. [1]

Recommended experiment: Wrap one RISCue register conversion and one simulation time/distance calculation in quantities. Leave wire formats as explicit integers, then compare baseline and typed binaries for size, allocation activity and deterministic timing.
01 / Accessible introduction

What problem does mp-units solve?

In ordinary C++, double doesn't reveal whether a value is metres, seconds, volts, kelvins, clock ticks, or something else. A comment or suffix might explain it to a human; the compiler doesn't enforce it. mp-units represents a physical quantity as a number coupled to a unit and quantity specification.

Before: opaque scalardouble value = 42;Which physical quantity? Which scale?
→
After: typed meaning42 × metreCompiler tracks dimensions, scale and compatible operations.

It also distinguishes quantity kinds. Kinetic energy and potential energy are both expressed in joules, but an API can require one specific kind. The project illustrates this distinction in its own README. Its quantity_point models coordinates relative to an origin—for example, a temperature reading or a timestamp, where simply adding two absolute points is not meaningful. [1] [2]

02 / Internals

How does it work?

Compile-time representation

C++20 templates, concepts and compile-time unit descriptions encode dimensions and quantity kinds in types. Incorrect operations fail during compilation, before deployment.

Quantity arithmetic

Operators compose units: distance ÷ time produces speed; speed × time produces distance. Compatible scales can be converted under constrained rules.

Affine space

quantity describes a difference; quantity_point describes a location relative to an origin. This matters for temperatures, timestamps and sensor calibration offsets.

Representation is a choice

Choose integer or floating representations deliberately. Compile-time dimensional correctness does not prevent overflow, quantization error or invalid input measurements.

The project describes zero-runtime-overhead dimensional analysis. That is not a blanket guarantee of zero allocations in every feature or transitive dependency. Formatting, container usage and logging must be assessed separately for an allocation-free RTOS. [3]

05 / Practical code

A flight-distance invariant in C++20

The example below follows the upstream header, quantity and unit-symbol API. It checks that 250 metres/second for 4 seconds equals 1 kilometre, verifies automatic metre/kilometre comparison, and demonstrates a compile-time distinction between kinetic and potential energy. The mismatch is intentionally commented out.

// main.cpp · mp-units 2.5.x · C++20 · no console or heap calls
#include <mp-units/systems/isq.h>
#include <mp-units/systems/si.h>

using namespace mp_units;
using namespace mp_units::si::unit_symbols;

// A tiny distance calculation with units checked at compile time.
constexpr auto coast_distance = (250 * m / s) * (4 * s);
static_assert(coast_distance == 1 * km);
static_assert(1 * km + 50 * m == 1050 * m);

// Two energy kinds use joules but mean different things.
constexpr int accept_kinetic([[maybe_unused]]
                             quantity<isq::kinetic_energy[J]> energy)
{
  return 0;
}

int main()
{
  quantity<isq::kinetic_energy[J]> kinetic = 123 * J;
  quantity<isq::potential_energy[J]> potential = 123 * J;
  // accept_kinetic(potential);  // Uncomment: must fail to compile.
  return accept_kinetic(kinetic);
}

Expected behavior: compile successfully and return 0. Removing the comment from accept_kinetic(potential) should make compilation fail; in a pilot, make this a separate negative-compile test. Unlike runtime assertions, static_assert is evaluated by the C++ compiler.

Validation boundary: this is an original adaptation of documented maintainer syntax and has been manually reviewed, but was not compiled in this environment. The upstream dependency could not be fetched into the local compiler sandbox. Do not interpret a source-level review as a green C++ build.
06 / Build integration

Pin, build and measure with Conan / CMake / Ninja

The upstream installation guide describes Conan as the recommended integration route and lists mp-units/2.5.0 in its published-release example. A separate testing stream lists 2.6.0; do not silently substitute a testing channel for a pinned release. Use find_package and mp-units::mp-units for CMake consumers. [3]

conanfile.txt

[requires]
mp-units/2.5.0

[generators]
CMakeDeps
CMakeToolchain

[layout]
cmake_layout

CMakeLists.txt

cmake_minimum_required(VERSION 3.23)
project(mpunits_probe LANGUAGES CXX)
find_package(mp-units CONFIG REQUIRED)
add_executable(mpunits_probe main.cpp)
target_compile_features(mpunits_probe PRIVATE cxx_std_20)
target_link_libraries(mpunits_probe PRIVATE mp-units::mp-units)

Local build sequence

# Use Conan 2 with a configured C++20-capable profile.
conan install . -s build_type=Release -s compiler.cppstd=20 --build=missing
# Conan generates CMake user presets; names can vary by profile.
cmake --preset conan-default
cmake --build --preset conan-release

Use a Conan profile configured for the installed compiler; generated preset names can differ. Select Ninja through your Conan/CMake generator configuration. For vendoring without Conan, upstream specifically directs consumers to src/CMakeLists.txt rather than the repository's development-only top-level CMake file, while warning that dependencies and flags remain the integrator's responsibility.

Embedded-specific options: upstream documents MP_UNITS_API_FREESTANDING=ON for the -ffreestanding configuration, and a contracts option whose handler/dependencies deserve separate inspection. Avoid bringing iostream/format into target builds just to print quantities. The README's no-external-dependencies claim applies to the core; the published installation recipe still manages optional features and integrations. [3]

07 / Tradeoffs

Safety is real; portability is a separate test

AxisAdvantageEngineering cost / condition
Dimensional safetyErrors visible at compile time.Requires careful modeling of quantity kinds, especially when one unit has multiple meanings.
Runtime budgetUnit algebra resolves at compile time for supported operations.Prove no extra code, allocations or WCET regressions with your actual target binary.
Compile + toolchainModern C++20 API and standard CMake target.Template instantiation and compiler capability matter; upstream flags specific compiler exclusions.
FreestandingDocumented mode and upstream CI.Not proof of interoperability with a custom RISC-V core, RTOS libc, exceptions or board support package.
Data interchangeUnits make in-process APIs safer.Wire formats/FFI still require explicit scale, numeric type, rounding and endian rules.
EvolutionActively maintained and part of a C++ standardization effort.Template API and supported toolchains may change; pin versions and build a migration test.

The upstream compiler matrix (as reviewed October 25, 2026) lists minimum GCC 12+, Clang 16+ excluding Clang 19, and MSVC 19.5+, with more detailed feature-specific limits; consult it before any cross-compiler rollout. [4]

08 / Licensing + integration

The core is MIT; examples deserve a separate look

The root LICENSE.md grants standard MIT permission to use, modify, redistribute, sublicense and sell, subject to preserving its copyright and permission notice. This is generally favorable to open-source and proprietary tooling. It is not a warranty of fitness for high-reliability applications.

Do not assume every copied sample carries the same licensing terms: example/capacitor_time_curve.cpp has its own GPL-3.0-or-later notice. This report links to that example rather than reproducing its code. For embedded targets also review third-party notices in any selected package dependencies or optional integrations.

Suggested integration discipline: lock the package revision; keep an SPDX/notice inventory; confine unit conversion to explicit ingress/egress boundaries; test overflow and rounding; audit build flags and generated object code. C++ quantity types should not be treated as a stable binary wire format.

  • Pending: real C++20 compile, intentional negative-compile, Conan/Ninja build and RISC-V freestanding cross-compile.
  • Pending: target allocation instrumentation, linker map/size comparison, compiler warnings and WCET measurement.

Minimal proposed acceptance test

Host: clean Conan 2 / CMake / Ninja build; successful static_assert test; expected failure of incompatible energy-kind call; compile on at least GCC and Clang. Embedded: freestanding build with the real RISCue toolchain, no unexpected unresolved runtime symbols or heap calls, same numerical results as plain scalar baseline, measured binary size and cycles within agreed budget. Interface: round-trip ADC volts and discrete simulation ticks through explicit boundary conversions and test saturation behavior.
