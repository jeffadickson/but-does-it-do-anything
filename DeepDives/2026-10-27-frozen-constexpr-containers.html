01 / Engineering verdict

Frozen is interesting because it moves lookup construction out of boot time.

For known, stable vocabularies—such as instruction mnemonics, status labels, and trace-event names—compile-time initialized containers can replace runtime map setup. Frozen is a header-only, Apache-2.0 C++ library with map, unordered_map, set and unordered_set variants. It supports C++14 and fits C++20; its maintainer describes the library as stable and in maintenance mode. [1]

C++14+C++20 compatible
Fixed keysno runtime insertion
O(1)*author's unordered lookup claim
Apache-2.0permissive license
Best first experiment: Benchmark a fixed VeloSim diagnostic name table or a RISCue host-tool instruction-name table against a switch and a sorted std::array. Measure compiler time, object size, memory layout and target cycles; do not assume a faster result.

*Frozen guarantees its generated unordered hash structure has no collisions among stored keys. This does not guarantee identical CPU cycles for variable-length strings or prove a whole routine's WCET. [1] [2]

02 / How it works

The key set is a compile-time commitment.

Ordinary std::unordered_map exists for dynamic data: buckets can be constructed or resized while the program runs. Frozen instead accepts a fixed element count and builds table data during constant evaluation. For unordered_* structures it seeks a collision-free arrangement for the known keys, using auxiliary metadata. The author describes linear extra storage and O(1) lookup relative to the number of stored keys. [1] [2] [3]

ContainerTypical useTradeoff
frozen::mapImmutable ordered-key tableDifferent lookup algorithm than the perfect hash
frozen::unordered_mapFixed-key perfect-hash lookupCompile-time generation cost and hash metadata
frozen::set / unordered_setMembership checksNo insert/delete after compile
Frozen string needle searchFixed-pattern BM/KMP searchSeparate facility, not a generic parser

A constexpr map has immutable keys and mapped values. Upstream also describes constinit-compatible fixed-key maps whose values can be changed at runtime. The keys still cannot be inserted or replaced. For writable tables, usual data-race rules apply. A constant-initialized object is not automatically guaranteed to reside in ROM on every embedded target. [1]

04 / Documented adoption

Real integration evidence, not invented installations.

DIRECT SOURCE EVIDENCE

LIEF: PE executable-format enumeration names

The open-source LIEF binary-format library has a src/frozen.hpp wrapper. With LIEF_FROZEN_ENABLED, its CONST_MAP macro uses constexpr frozen::map; otherwise it falls back to a standard map. In src/PE/EnumToString.cpp, a function uses this macro for translating PE algorithm enum values into names. The build also exposes a LIEF_DISABLE_FROZEN option. This proves conditional integration in real source code, not that every released LIEF binary enables the option. [5] [6] [7]

MAINTAINER EXAMPLE

ELF relocations and other sample programs

Frozen's upstream examples directory includes an i386 ELF relocation enum-to-string example with 41 entries, plus HTML-entity and pixel-art examples. These are published example programs. They are not evidence that spacecraft, hardware products, or the user's repositories deploy Frozen. [4] [8]

PACKAGE ECOSYSTEM

vcpkg distribution

The vcpkg Frozen package page records 1.2.0, Apache-2.0 licensing and package-level reverse dependencies including lief, ormpp and yalantinglibs. Registry relationships establish packages, not production deployment. [9]

No claim is made that JPL, NASA, RISCue, VeloSim, or any flight system currently uses Frozen.

06 / Practical C++20 example

A bounded mnemonic classifier with explicit misses.

This application uses the published frozen::unordered_map, frozen::string, find() and end() APIs. static_assert checks the intended known/missing behavior at compile time. RISCue naming is proposed, not a snippet from its repository. [1] [3]

main.cpp · target the reviewed upstream source
// Illustrative RISCue host-tool classifier, C++20
#include <frozen/unordered_map.h>
#include <frozen/string.h>
#include <cstdint>

enum class Op : std::uint8_t { add, load, store, branch, unknown };

constexpr frozen::unordered_map<frozen::string, Op, 4> kOpcode = {
    {"ADD", Op::add},
    {"LD",  Op::load},
    {"ST",  Op::store},
    {"BEQ", Op::branch},
};

constexpr Op classify(frozen::string mnemonic) {
    // Missing keys are normal input; avoid throwing at().
    const auto it = kOpcode.find(mnemonic);
    return it == kOpcode.end() ? Op::unknown : it->second;
}

static_assert(classify("ADD") == Op::add);
static_assert(classify("BEQ") == Op::branch);
static_assert(classify("DIV") == Op::unknown);

int main() {
    return classify("LD") == Op::load ? 0 : 1;
}

Why not at()? On a miss, upstream at() throws std::out_of_range in exception-enabled builds; in disabled-exception configurations or with FROZEN_NO_EXCEPTIONS, it may call std::abort. find() avoids this for ordinary unknown input. [1] [3]

07 / CMake and Ninja

Pin a revision before judging integration.

The project's CMake configuration defines frozen as an INTERFACE target, with alias frozen::frozen, and declares a C++14 minimum. The example pins the upstream master SHA observed on October 27, 2026; a moving master URL is not a reproducible dependency version. [10] [12]

CMakeLists.txt · small host-side lab
cmake_minimum_required(VERSION 3.20)
project(frozen_lab LANGUAGES CXX)
include(FetchContent)

# Pin reviewed source revision, not a moving branch.
FetchContent_Declare(frozen
  GIT_REPOSITORY https://github.com/serge-sans-paille/frozen.git
  GIT_TAG d53e0a11578d56dc331dc267c2084d52bcdee1d9
  GIT_SHALLOW FALSE)
FetchContent_MakeAvailable(frozen)

add_executable(frozen_lab main.cpp)
target_compile_features(frozen_lab PRIVATE cxx_std_20)
target_link_libraries(frozen_lab PRIVATE frozen::frozen)
Shell · requires network for first FetchContent download
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/frozen_lab   # Expected exit status: 0 (Unix-like shell)
# ctest --test-dir build only after registering actual tests

Alternative: vendor include/frozen and add an interface include target for fully offline or tightly controlled firmware builds. On Windows, run the executable from the selected generator output directory. vcpkg also distributes Frozen; pin the vcpkg registry baseline to make that route reproducible. [9]

08 / Honest tradeoffs

Bounded lookup storage has a price.

DimensionBenefitCost or required verification
StartupNo ordinary runtime table construction for constant initializationConfirm linker and static initialization behavior
MemoryNo per-key runtime heap nodes in the fixed tableHash metadata, stored values, code and ROM/RAM bytes remain
LookupPerfect-hash layout for known keysHashing string bytes and memory accesses take time
Compile timeComputes layout before executionLarge key sets can hit constexpr step limits
Change controlVocabulary fixed in source controlCannot load arbitrary new keys dynamically
Missing keysfind() allows explicit miss handlingat() may throw or abort
ConcurrencyImmutable constexpr data is read-onlyMutable mapped values need synchronization
MaintenanceSimple header-only integrationUpstream explicitly says maintenance mode

For small vocabularies a hand-written switch, gperf, or sorted std::array may outperform Frozen on real hardware. The author's CppCon presentation reported some cases where generated gperf code was faster before hashing customization. Benchmark rather than repeat an optimistic percentage. [2]

09 / Measurement design

Treat adoption as an experiment, not a slogan.

Common test inputs

Use the identical set of keys for four implementations: switch, sorted std::array, frozen::map, and frozen::unordered_map. Run hit-heavy, miss-heavy and mixed workloads; include strings of varying length and case.

Record honest metrics

Measure compiler elapsed time, .text/.rodata/.data/.bss sizes, zero-allocation evidence for the measured path, warm and cold lookup cycles, p50/p99, and worst observed latency. Benchmark both host and target builds.

Adoption gate (proposed): Require bit-for-bit equivalent lookup outcomes, no accidental allocations in the measured embedded path, acceptable binary footprint, tolerable compilation cost and target timing within budget. There is no measured performance result in this report.
10 / License and release status

Apache-2.0, maintenance mode, version ambiguity.

Frozen's top-level license is Apache License 2.0, including copyright and patent grants as well as redistribution requirements such as license copying, preservation of relevant notices and marking modified files; observe any upstream NOTICE material where applicable. Review third-party notices and header vendoring with your project. This is a developer summary, not legal advice. [11]

The upstream README calls master the stable default and describes the project as in maintenance mode. The checked master SHA d53e0a11578d56dc331dc267c2084d52bcdee1d9 is dated October 9, 2026. A vcpkg package is labeled 1.2.0, while the checked upstream CMakeLists.txt declares project(frozen VERSION 1.1.0). Use pinned source or a locked package baseline, not assumptions about these different numbers. [1] [9] [10] [12]

11 / Technical review

Evidence checked; compilation not claimed.

The Frozen upstream README, unordered_map.h and string.h were inspected for the names and semantics used in the example, including constant evaluation and miss behavior. Its current CMake file confirms frozen::frozen. LIEF's own source files substantiate only conditional integration, not a blanket deployment claim. [1] [3] [5] [6] [10]

Unverified C++ build: The execution environment could not resolve github.com for git clone, and Frozen headers were not already installed. The code has been source/API-reviewed, but was not compiled or linked against the full upstream library. No runtime benchmark, allocation trace, MCU cycle count, or library unit-test pass is claimed.

The HTML has semantic sections, an internal contents index, accessible button labels and feedback, mobile-responsive CSS, escaped code, visible focus styles and reduced-motion preferences. Its JavaScript demo is educational and is not a Frozen implementation.
