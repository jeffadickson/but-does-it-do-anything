nanoprintf: the format string is a contract

A near-minimal, allocation-free formatting library can be excellent for embedded diagnostics. It is not inherently a type-safe logger, a constant-time primitive, or a deterministic trace protocol.

01. Engineering decision

Recommended use: small, bounded conversion of validated integer fields into caller-owned buffers for a low-priority diagnostic actor. Do not embed text formatting in a hard-deadline scheduler transition or ISR and expect that the library's absence of heap allocation makes downstream I/O safe.

Zero heap callsUpstream claim for the formatter, not for user callbacks or the logging pipeline.
480 bytesUpstream reported minimum integer-only text size on Cortex-M0/M4 at -Os. Not measured here.
Four APIssnprintf/vsnprintf, pprintf/vpprintf. Format behavior is feature-configurable.

Design rule: the authoritative trace is structured data. Its rendered text is disposable. Formatting overflow, UART latency, and diagnostics queue congestion must never affect state transitions.

This report reviews upstream v0.8.1, released September 25, 2026 (commit bebaecbeaf430e36a2d30d31a2fed4e098388c93). The release contains a useful explicit conformance inventory that makes the boundary of the implementation auditable. [1] [3]

02. What nanoprintf is—and isn't

Charles Nicholson's nanoprintf is a single-header C99 formatting implementation usable from C++20. It supplies snprintf-style and callback-driven output with an unusually small embedded footprint. It does not own a queue, allocate a string, schedule a task, transport bytes, lock a shared sink, or implement a typed telemetry schema. The public header is installed in consumers; one translation unit defines NANOPRINTF_IMPLEMENTATION. [2] [5]

Upstream documented

Fixed feature switches; stack-only internal storage; no allocator calls; documented snprintf length/truncation semantics; C++ examples and tests.

Integrator must demonstrate

Target stack watermark, timing bound, linker symbols, queue overload policy, ISR interaction, format-string inventory and replay equivalence.

The repository offers an explicit choice of Unlicense or Zero-Clause BSD (0BSD). It is not MIT-licensed. See section 13 for distribution guidance. [4]

03. The API and ownership path

FunctionMeaningTypical application
npf_snprintfWrite at most the capacity; return chars required, excluding NULBounded local text buffer
npf_vsnprintfSame with va_listVariadic wrapper
npf_pprintfCall a user-supplied function for each output characterCustom sink; caller owns synchronization and timing
npf_vpprintfCallback output via va_listVariadic sink adapter

The snprintf variants report the count they would have written given sufficient space. At capacity N > 0, default overflow terminates the clipped string in the last slot; a return value >= N means truncation. nullptr with zero size can be used for a length-only query. An optional NANOPRINTF_SNPRINTF_SAFE_EMPTY_STRING_ON_OVERFLOW configuration empties the buffer on overflow. [2]

04. The critical format-specifier trap

High-impact finding: if a conversion family is compiled out, nanoprintf prints the unsupported specifier literally without consuming its variadic argument. The next conversion can therefore read an argument of the wrong type. The upstream README and conformance notes expressly describe this condition. It is not merely a cosmetic logging problem. [2] [3]

Anti-pattern — do not execute or rely on its output

// Float formatting has been disabled at compile time.
// The %f argument is not consumed: the later %u reads incorrectly.
npf_snprintf(buf, sizeof buf, "%f %u", 1.25, 7u);

Mitigation: restrict formats to reviewed literals; audit every specifier against the selected configuration; enable GCC/Clang format warnings; ban dynamic format strings; and prefer small, typed wrappers for critical records. Passing untrusted text as a %s argument is different from using that text as the format string. Type annotations cannot by themselves understand a nondefault nanoprintf feature profile.

A second caution is floating point. Upstream's conformance inventory [3] documents limited conversion buffers, rounding deviations, fixed rounding direction, and unsupported wide-character/locale cases. Golden text is not automatically portable or C11-exact.

05. A bounded C++20 adapter

This deliberately narrow sample uses %u only, with matching unsigned arguments and inline storage. Failure publishes no partial string. npf_port.h is the project wrapper defined below.

src/trace_format.cpp — illustrative, source-reviewed example

#include <array>
#include <cstddef>
#include <cstdint>
#include "npf_port.h"

enum class TraceStatus : std::uint8_t { ok, overflow };

struct TraceLine {
    std::array<char, 64> bytes{};
    std::size_t length = 0;
    TraceStatus status = TraceStatus::ok;
};

[[nodiscard]] TraceLine format_event(
    unsigned tick, unsigned event_id) noexcept
{
    TraceLine line{};
    const int required = npf_snprintf(
        line.bytes.data(), line.bytes.size(),
        "tick=%u event=%u", tick, event_id);

    if (required < 0 ||
        static_cast<std::size_t>(required) >= line.bytes.size()) {
        line.bytes[0] = '\0'; // Suppress partial messages.
        line.status = TraceStatus::overflow;
        return line;
    }
    line.length = static_cast<std::size_t>(required);
    return line;
}

Why >=? A buffer requires an extra byte for NUL. Exactly capacity non-NUL characters are already one byte too many. An empty valid message must not be confused with an overflow result. The status is the contract. This sample is proposed for integration; it was not compiled against upstream v0.8.1 or measured on a target in this run.

06. A deliberately restricted feature profile

The upstream default includes floats and selected formatting features. An integer-only profile can reduce size and remove numeric conversion code, but it must be paired with a strictly audited format inventory. When any core feature flag is explicitly set, upstream requires the others to be set too. Optional scientific, hex float, fixed-width and division-free features default off. [5]

include/npf_config.h — example policy

#pragma once
#define NANOPRINTF_USE_FIELD_WIDTH_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_PRECISION_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_FLOAT_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_LARGE_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_SMALL_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_BINARY_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_WRITEBACK_FORMAT_SPECIFIERS 0
#define NANOPRINTF_USE_ALT_FORM_FLAG 0
#define NANOPRINTF_USE_FLOAT_SINGLE_PRECISION 0

This profile permits ordinary %u, %d and %x conversions (with appropriately typed arguments) but intentionally not %f, %zu, %lld, width or precision. Do not quietly enable those in one target without updating the source audit and golden trace configuration. Unsupported specifiers can desynchronize argument consumption.

07. CMake/Ninja: one implementation, one profile

Vendor the stamped v0.8.1 distribution header into third_party/nanoprintf/, retain the upstream LICENSE, and pin the tag and commit in a third-party manifest. The release notes recommend the stamped asset rather than an autogenerated source archive's unstamped header. [1]

include/npf_port.h

#pragma once
#include "npf_config.h"
#include "nanoprintf.h"

src/npf_impl.cpp — the only implementation translation unit

#define NANOPRINTF_IMPLEMENTATION
#include "npf_port.h"

CMakeLists.txt — Ninja-compatible, no network fetch

cmake_minimum_required(VERSION 3.22)
project(riscue_trace_adapter LANGUAGES CXX)

add_library(npf STATIC src/npf_impl.cpp)
target_include_directories(npf PUBLIC
    "include"
    "third_party/nanoprintf")
target_compile_features(npf PUBLIC cxx_std_20)

add_library(trace_format STATIC src/trace_format.cpp)
target_link_libraries(trace_format PUBLIC npf)

# Configure with your actual target toolchain:
# cmake -S . -B build -G Ninja
# cmake --build build --verbose

All consumers include the same npf_port.h wrapper. Add your board toolchain, warning policy, no-exceptions rules if applicable, source hashes, map generation, and test executables in the platform build. The example intentionally avoids build-time network dependencies, but it is not an end-to-end freestanding toolchain qualification.

08. Proposed RISCue, HSM and active-object fit

Appropriate boundary

A low-priority diagnostic actor consumes typed events from a bounded queue, formats a fixed allowlist of fields, checks overflow, and emits to a capacity-aware sink.

Inappropriate boundary

An ISR or scheduling-critical transition formats strings synchronously, with a potentially blocking per-byte UART callback or a contested shared buffer.

The queue's full policy must be explicit: reject and count, overwrite oldest under a documented lossy contract, or backpressure only where permitted. A log write must never change HSM scheduling or event dispatch. The formatter's internal lack of allocation does not establish the behavior of npf_pprintf's callback.

Suggested requirements, not existing RISCue requirements: RT-LOG-001: no dynamic allocation in the adapter; RT-LOG-002: overflow yields explicit status and zero publishable bytes; RT-LOG-003: no formatting on ISR/critical dispatch path; RT-LOG-004: trace dropping cannot alter state transitions. Attach tests, map-file evidence, timing traces, and design reviews to each.

09. Deterministic simulation and replay

Persist typed events and logical timestamps as the canonical record. Formatting is a derived view; a text-only golden trace can change with profile flags, compiler, integer widths, or a formatter upgrade. Freeze a versioned rendering profile where byte-for-byte text compatibility is a requirement.

  • Resolve order in the deterministic scheduler/recorder, not by arrival order at a shared output sink.
  • Use logical time; never introduce wall-clock sampling just to pretty-print an event.
  • Check exact output on zero, maximal integers, boundaries and truncation; use an independent host oracle for supported conversions.
  • Replay with logging enabled, disabled and intentionally overflowing and compare the same canonical state and event hashes.

These are proposed applications to RISCue and deterministic simulation. No upstream evidence supports a claim of existing RISCue/VeloSim integration.

10. Engineering tradeoffs

PropertyStrengthQualification gap
AllocationFormatter uses no heapSink and caller may; audit complete call path
Code/stack sizeSmall upstream numbersMeasure target map, stack watermark, compiler helpers and LTO effects
TimingSynchronous direct conversionNot constant-time: length, width, input values and callbacks vary
Format safetyCompiler format attributes on supported compilersVariadic calls remain weakly typed; compiled-out specifiers shift argument reads
Truncationsnprintf-style buffer boundCaller must inspect returned required count and handle failure
ConcurrencyInternal stack-local stateShared buffers/callbacks still race or block
Floating pointOptional and configurablePrecision/rounding deviations and finite conversion buffer; golden traces require tests
Text semanticsASCII-oriented firmware utilityNo wide-character/locale transformations

No heap ≠ bounded WCET. Code-size and stack figures published by upstream cannot be substituted for timing measurements on the actual RTOS, compiler and CPU. A UART sink may dominate everything the formatter saved.

11. Verifiable adoption versus suggested use

Publicly verifiable: upstream maintains C++ examples, tests and cross-platform builds. The Android Open Source Project's external/nanoprintf mirror establishes downstream source presence. It does not, without a dependency/build investigation, establish that a particular device image links the library or that nanoprintf is active in production. [7]

Not verified: deployment in RISCue, VeloSim, flight software, JPL systems, or any particular production firmware. The actor, telemetry and simulator examples here are proposals. Public repo counts, stars and example code are not deployment evidence.

12. A compact qualification campaign

  1. Pin provenance: hash the v0.8.1 header; retain exact build flags, target triple, CMake/Ninja and compiler versions.
  2. Audit format grammar: enumerate all literals and argument types; fail builds on mismatches and unsupported specifiers; enable -Wformat=2 when supported.
  3. Test buffers: capacities 0, 1, exact fit, one short and large; test null/zero length requests and explicit failure behavior.
  4. Test integer values: signed extrema, unsigned maxima, zero, flags actually enabled and exact expected bytes.
  5. Reject bad calls: static or analyzer checks catch disabled conversions and dynamic formats before execution; do not depend on undefined or shifted-varargs output.
  6. Exercise concurrency: independent task-owned buffers, preemption, sink contention and full-output queue policies; measure callbacks separately.
  7. Measure target: text/rodata, stack high-water, worst observed cycles and compiler helper symbols; include LTO and debug/release variants.
  8. Assert replay invariance: identical canonical event/state hashes across disabled logging, enabled logging and loss/truncation conditions.

Acceptance: zero unresolved format mismatches; target build and timing evidence; documented drop/overflow policy; and replay equivalence. The campaign is recommended, not claimed completed.

13. Licensing, maintenance and supply chain

Upstream LICENSE explicitly grants a choice of Unlicense (public-domain dedication plus fallback terms) and 0BSD (a short permissive copyright license). It applies to library source, build code and tests. No MIT obligation attaches to nanoprintf itself. Preserving its license text, provenance and version is a sensible supply-chain policy. Dependencies obtained for upstream tests have their own terms; the runtime header does not require the upstream test bootstrap.

For an organization that prefers a conventional permissive license over a public-domain dedication, evaluate using the 0BSD alternative. Legal adoption decisions remain the organization's responsibility.
