01 / Executive assessment

The number isn't the meaning

Imagine an instrument driver with an int instrumentId, an int channelId, and an int eventId. The three identifiers might all equal 17. The machine sees integers; the engineer sees different concepts.

Vogen is a Roslyn source generator and analyzer. Declare a partial C# value type with [ValueObject<int>]; the build generates a wrapper, an explicit From(...) factory, equality, and optional validation and conversion support. Distinct wrappers become distinct types in function signatures, so accidental cross-wiring is diagnosed by the C# compiler. It does not instrument an RTOS, and it is not a runtime validation service.

Why it matters to your projects: BenchForge instrument and channel IDs, VeloSim event sequence numbers, and StressForge rules can be made less ambiguous. The real attraction is preventing categories of bad states, not faster arithmetic.

Documented

Generated wrappers, From validation, analysis of explicit misuse, configurable converters. See upstream README, FAQ and integration docs.

Not automatically guaranteed

Allocation freedom in all integrations, total runtime prevention of default structs, Native AOT compatibility of every serializer, or better benchmark scores.

02 / Under the hood

Generated at compile time—not magic at runtime

  1. Declare the domain type. A partial struct identifies its primitive representation: [ValueObject<int>].
  2. Roslyn runs Vogen. At build time, Vogen emits the rest of the partial type. Its analyzer reports certain forbidden construction patterns.
  3. Construct through a factory. InstrumentId.From(17) applies the optional declared Validate(int) rule and returns an initialized value.
  4. Compile strongly typed call sites. The compiler rejects Connect(channel, instrument) when the method requires the reverse type order.
  5. Choose explicit adapters. For a minimal simulation core, Conversions.None keeps the wrapper free of Vogen-generated JSON/ORM converter glue.
Important nuance: C# structs always have a zero/default representation. Vogen's analyzer flags many explicit uses of default and new, but this is not a proof that all runtime paths—including generic arrays, reflection, and deserialization—cannot construct an uninitialized wrapper. Treat external boundaries as untrusted.
Illustration · int identifiers versus domain identifiersRead-only
// Two different concepts, yet the compiler only sees (int, int).
static void Connect(int instrumentId, int channelId) { /* ... */ }
Connect(channelId, instrumentId); // Compiles; silently swaps identifiers.

// With Vogen-generated types:
static void Connect(InstrumentId instrumentId, ChannelId channelId) { /* ... */ }
Connect(ChannelId.From(2), InstrumentId.From(17)); // Does NOT compile.

A complete minimal .NET 10 console app

The listings below follow the upstream attribute, factory, validation, and Conversions.None patterns. The sample has two distinct validated ID types, demonstrates a rejected invalid ID, and leaves an intentionally swapped call commented out to show how to trigger a compile error.

Program.cs · complete programC#
using Vogen;

var instrument = InstrumentId.From(17);
var channel = ChannelId.From(2);

Connect(instrument, channel);

// Uncomment to see a real C# type error (CS1503):
// Connect(channel, instrument);

// The application can handle bad data at its boundary.
try
{
    _ = ChannelId.From(-4);
}
catch (ValueObjectValidationException ex)
{
    Console.WriteLine($"Invalid channel: {ex.Message}");
}

static void Connect(InstrumentId instrument, ChannelId channel)
{
    Console.WriteLine($"Connecting instrument {instrument.Value}, channel {channel.Value}");
}

[ValueObject<int>(conversions: Conversions.None)]
public readonly partial struct InstrumentId
{
    public static Validation Validate(int value) =>
        value > 0 ? Validation.Ok :
        Validation.Invalid("Instrument IDs must be positive.");
}

[ValueObject<int>(conversions: Conversions.None)]
public readonly partial struct ChannelId
{
    public static Validation Validate(int value) =>
        value > 0 ? Validation.Ok :
        Validation.Invalid("Channel IDs must be positive.");
}

Expected behavior, not an execution claim: a valid connection line, then an invalid-channel exception caught and reported. Uncommenting Connect(channel, instrument) should cause a C# argument-type mismatch. Actual Vogen compilation and Native AOT linking must be verified in your development machine or CI.

Acceptance tests: valid positive IDs round trip through Value; zero/negative inputs reject; swapped parameters fail compilation (negative compilation test); static analyzers warn/error for explicit default; Release/Native AOT builds run independently. Include serialization/FFI cases only when needed.

07 / Native AOT and boundaries

Why source generation helps—and what still needs proving

A source generator emits C# at build time, so Vogen's basic numeric wrappers do not require runtime reflection to create their types. This makes the core concept attractive for Native AOT. But “source-generated” does not certify every converter, ORM, or dependency as trimming-safe; native publish and analyzer output are the real acceptance gates.

Good baseline

  • Use readonly partial struct for small immutable identifiers.
  • Specify Conversions.None unless conversion is explicitly required.
  • Pin Vogen 8.0.7, check generated output, and preserve Roslyn diagnostics in CI.
  • Run dotnet publish -r win-x64 -c Release with PublishAot=true.

Review integrations separately

  • Any reflection-based JSON/ORM pathways.
  • Native AOT and linker warnings (for example IL2xxx and IL3xxx).
  • Trimming of serializer metadata; explicit JsonSerializerContext where appropriate.
  • Exception behavior, public API serialization contracts, and interop layout.

Microsoft's documented IsAotCompatible analyzers help check library AOT safety; a successful generator invocation alone does not prove such compatibility. The same applies to .NET 10: the target SDK and the generator run in different compilation contexts.

Allocation claim scope: a small value-type wrapper may avoid per-instance heap allocation, but boxing, exception creation, formatting, strings, conversion and higher-level logging can still allocate. Do not market the whole application as allocation-free from this one library choice.

09 / Decision support

What else would we use?

Manual readonly record struct

No generator dependency; best for very few wrappers. Write and test validation, serialization, and explicit default semantics yourself.

StronglyTypedId

Another established C# source-generator approach emphasizing identifiers. Compare generated API, package maintenance, analyzer behavior and serializers before adopting. Do not assume feature equivalence.

SharpContracts / Z3

Separate concern: proof of method contracts and counterexamples. Vogen adds nominal domain types, not mathematical verification.

SharpUnits / mp-units

Physical dimensional analysis prevents mixing metres and seconds. Vogen prevents mixing domain identifiers; neither substitutes for the other.

Adoption gate: promote Vogen only if a two-type spike yields meaningful compile-time bug prevention, predictable codegen, supported CI/AOT output, and negligible measurable overhead in hot paths.
10 / Integration & license

Apache-2.0, not MIT

Vogen's upstream LICENSE is Apache License 2.0. It permits commercial and open-source use and includes a patent grant. Distribution of the covered software requires preserving the license and applicable notices; altered files require appropriate notices. Follow the full license for actual distribution scenarios, including any third-party package licenses.

For engineering governance, record the NuGet package version, license identifier Apache-2.0, source repository and resolved dependency graph in the SBOM. Pin dependencies, use lock files where appropriate, run package vulnerability checks, and review changes to the generator because it executes as part of the build. Package metadata states stable 8.0.7 was published 21 July 2026; 9.0.0-beta.1 exists but is prerelease.

A compile-time generator is not itself the same thing as a production framework service. Keep generated code, build-time package scope (PrivateAssets="all"), and any chosen runtime serializer dependencies separately documented.

11 / Technical review & acceptance

What was checked, and what was not

  • Source reconciliation: core API pattern checked against the maintainer's README and documentation; license and package version checked against GitHub and NuGet; Kentico dependency checked against its published package metadata.
  • Code analysis: sample uses officially documented [ValueObject<int>], From, Validate, Validation.Ok/Invalid, and Conversions.None interfaces.
  • HTML engineering: standalone CSS/JS and accessible label/legend navigation; keyboard-friendly demo with aria-live; responsive typography, visible focus, reduced-motion and print treatment.
  • Explicit limitations: this review does not claim a successful .NET build, Vogen unit test run, codegen compilation, Native AOT publish, or product-level performance measurement. Those need a .NET SDK, NuGet access and platform compiler toolchain.
