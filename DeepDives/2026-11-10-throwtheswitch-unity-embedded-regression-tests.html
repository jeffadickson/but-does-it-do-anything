01 / Verdict

A small harness. An executable contract.

Unity is a C unit testing framework for embedded targets. Its core is one implementation file (unity.c) and two headers. A test calls TEST_ASSERT_*; the runner invokes UNITY_BEGIN(), RUN_TEST() and UNITY_END(). Failure is reported with the named test and source location. The library can be included in ordinary CMake/Ninja builds.

Fit: test bounded queues, device-support code, simple protocol encoders and low-level C components that sit beneath a C++20 RTOS. Put Unity in the test executable, not the released scheduler. Do not treat a unit test as proof of worst-case latency or system correctness.

Uniqueness check: existing DeepDives cover ETL, QP/C++, Boost.Ext.SML, HFSM2, fixed-capacity containers, and RapidCheck. Unity is a distinct library for hand-written tests; RapidCheck generates/shrinks inputs and is better suited to host-side exploration.

02 / How it works

Arrange. Act. Assert. Report.

  1. Arrange: initialize a fixed 4-slot queue.
  2. Act: push and pop messages, including boundary cases.
  3. Assert: use TEST_ASSERT_EQUAL_UINT8(expected, actual) to catch wrong values.
  4. Report: UNITY_END() returns the suite's failure count; make a nonzero count fail CTest/CI.

Unity maintains global runner state and normally routes failure through a nonlocal-abort mechanism involving setjmp/longjmp on hosted targets. Output defaults to a configurable character sink, typically backed by putchar. Neither execution time nor the I/O implementation is inherently deterministic.

C++20 caution: nonlocal assertion failures may skip nontrivial C++ destructors, which can invoke undefined behavior. Use C-style test functions or carefully bounded C++ wrappers; for RAII-heavy test bodies, prefer a native C++-aware framework. The example below uses C11 intentionally, while its queue header is C++20-compatible.

04 / Interactive browser experiment

Bug hunt: the vanishing event

A 4-slot queue must reject a fifth push without replacing old events. Run the five checks, then inject a deliberate overwrite bug. Which assertion catches it?

Starting test bench

    This interactive simulation is written in plain JavaScript. It models the same queue scenarios; it does not execute Unity itself or qualify firmware.

    Test the reasoning

    Why reject a full queue?

    Silent overwrites may erase an alarm, message or state transition. Overwrite is possible as a separately specified policy, but this queue's contract requires explicit refusal.

    Why run the same test sequence more than once?

    Fixed inputs make regressions comparable. They detect some errors reliably, but do not explore every possible interleaving or concurrency bug.

    05 / Code you can build

    A four-slot queue, five tests.

    Save these three files together. The production header uses caller-owned storage, checks full/empty, and makes failed push preserve the queued messages. q must be non-null. In this simple C11/C++20-compatible module, the operations do not request heap allocation.

    bounded_queue.h — production header
    #ifndef BOUNDED_QUEUE_H
#define BOUNDED_QUEUE_H
#include <stdint.h>
#include <stdbool.h>
#define QUEUE_CAPACITY 4u
typedef struct {
    uint8_t slots[QUEUE_CAPACITY];
    uint8_t head, tail, count;
} BoundedQueue;
/* Contract: q must be non-NULL; caller owns storage. */
static inline void queue_reset(BoundedQueue *q) {
    q->head = q->tail = q->count = 0;
}
static inline bool queue_push(BoundedQueue *q, uint8_t value) {
    if (q->count == QUEUE_CAPACITY) return false;
    q->slots[q->tail] = value;
    q->tail = (uint8_t)((q->tail + 1u) % QUEUE_CAPACITY);
    ++q->count;
    return true;
}
static inline bool queue_pop(BoundedQueue *q, uint8_t *out) {
    if (q->count == 0 || out == 0) return false;
    *out = q->slots[q->head];
    q->head = (uint8_t)((q->head + 1u) % QUEUE_CAPACITY);
    --q->count;
    return true;
}
#endif
    test_queue.c — five Unity tests
    #include "unity.h"
#include "bounded_queue.h"
void setUp(void) {}
void tearDown(void) {}

void test_fifo_order(void) {
    BoundedQueue q; uint8_t out = 0;
    queue_reset(&q);
    TEST_ASSERT_TRUE(queue_push(&q, 10));
    TEST_ASSERT_TRUE(queue_push(&q, 20));
    TEST_ASSERT_TRUE(queue_pop(&q, &out));
    TEST_ASSERT_EQUAL_UINT8(10, out);
    TEST_ASSERT_TRUE(queue_pop(&q, &out));
    TEST_ASSERT_EQUAL_UINT8(20, out);
}
void test_full_queue_rejects_without_damage(void) {
    BoundedQueue q; uint8_t out = 0;
    queue_reset(&q);
    for (uint8_t i = 1; i <= 4; ++i)
        TEST_ASSERT_TRUE(queue_push(&q, i));
    TEST_ASSERT_FALSE(queue_push(&q, 99));
    TEST_ASSERT_EQUAL_UINT8(4, q.count);
    TEST_ASSERT_TRUE(queue_pop(&q, &out));
    TEST_ASSERT_EQUAL_UINT8(1, out);
}
void test_wraparound_preserves_fifo(void) {
    BoundedQueue q; uint8_t out = 0;
    queue_reset(&q);
    for (uint8_t i = 1; i <= 4; ++i)
        TEST_ASSERT_TRUE(queue_push(&q, i));
    TEST_ASSERT_TRUE(queue_pop(&q, &out));
    TEST_ASSERT_TRUE(queue_pop(&q, &out));
    TEST_ASSERT_TRUE(queue_push(&q, 5));
    TEST_ASSERT_TRUE(queue_push(&q, 6));
    for (uint8_t i = 3; i <= 6; ++i) {
        TEST_ASSERT_TRUE(queue_pop(&q, &out));
        TEST_ASSERT_EQUAL_UINT8(i, out);
    }
}
void test_empty_pop_keeps_output(void) {
    BoundedQueue q; uint8_t out = 77;
    queue_reset(&q);
    TEST_ASSERT_FALSE(queue_pop(&q, &out));
    TEST_ASSERT_EQUAL_UINT8(77, out);
}
void test_reset_discards_pending_events(void) {
    BoundedQueue q; uint8_t out = 0;
    queue_reset(&q);
    TEST_ASSERT_TRUE(queue_push(&q, 42));
    queue_reset(&q);
    TEST_ASSERT_EQUAL_UINT8(0, q.count);
    TEST_ASSERT_FALSE(queue_pop(&q, &out));
}
int main(void) {
    UNITY_BEGIN();
    RUN_TEST(test_fifo_order);
    RUN_TEST(test_full_queue_rejects_without_damage);
    RUN_TEST(test_wraparound_preserves_fifo);
    RUN_TEST(test_empty_pop_keeps_output);
    RUN_TEST(test_reset_discards_pending_events);
    return UNITY_END();
}

    06 / License & build

    Put the dependency where tests live.

    Unity is MIT-licensed (copyright Throw The Switch contributors; retain the upstream copyright and license notice). Its v2.7.0 release was published July 16, 2026. The example FetchContent pins the release tag; for highly reproducible offline builds, vendor the audited source or pin its immutable commit SHA. First-time FetchContent requires network access.

    On an MCU, override UNITY_OUTPUT_CHAR for serial, semihosting or another appropriate output channel. Measure real binary size, static data, stack high-water mark, and any transitive allocator calls. Unity's minimal core is not a global zero-allocation guarantee, especially when standard C library output and optional runners are used.

    Isolate unity.c to the test target. The same bounded_queue.h can compile in firmware; nothing about this toy sample obliges an embedded production build to include the test framework. Unity's MIT license permits modifications and redistribution with its notice, without making safety-certification or warranty claims.

    07 / Tradeoffs

    Small does not mean automatically qualified.

    ConcernStrengthEngineering caveat
    FootprintOne C implementation and two headersMeasure ROM/RAM/stack on your compiler and target.
    ReproducibilityNamed deterministic input casesReal hardware clocks and interrupt interleavings need separate controls.
    HeapShown queue makes no allocation requestsDo not extrapolate to Unity, printf, instrumentation, CI runners or target libc.
    ConcurrencyEasy single-runner mental modelGlobal state is not a reentrant test harness; serialize runs.
    C++20C and C++ caller compatibility for the queueFailure control flow may violate C++ RAII expectations.
    CoverageGood exact regression contractsCoverage, fuzzing, mutation tests, hardware-in-loop still needed.
    DeploymentActual ESP-IDF integration documentedThat does not certify RISCue's behavior or timing.
    Explicit nonclaims: hard-real-time timing, thread safety, production certification, universal zero-heap execution, and correctness of untested conditions are not established by this report.

    08 / Next useful experiment

    Kill a mutant; preserve its trace.

    1. Isolate one RISCue C-facing bounded queue or peripheral utility with explicit full/empty behavior.
    2. Run this five-case suite plus capacity boundary vectors in Debug and Release with GCC and Clang.
    3. Introduce a one-line “overwrite when full” mutation; verify a test fails and preserve the message sequence.
    4. Add CTest in CI; capture return status and compiler identity with the test evidence.
    5. Measure runtime, stack, output, allocation and integration separately on any target hardware before claiming platform qualification.
    Recommendation: a practical small assertion framework for embedded C surfaces. Pair its precise regression cases with host-side RapidCheck sequence exploration; use a C++-aware harness for nontrivial C++ objects.
