01 / The concrete problem

It starts as a few words in a string.

An application accepts a formula, a command, a filter, or a small configuration language. The first implementation splits on spaces or punctuation. That can be exactly the right amount of engineering.

The first version

gain 2.5
offset 0.1

Two words, no nesting, no quoting, no ambiguity. A short validation routine may be all you need.

The change request

gain (base + trim) * 2.5
label "rack 2 / channel A"

Now spaces can belong inside a value. Parentheses nest. Operators have precedence. Error locations matter.

The awkward part is no longer finding separators. It is recognizing structure. Splitting (1+2)*3 on plus signs loses the fact that the addition is a group. Treating 1+2*3 as a left-to-right operation sequence gives the wrong arithmetic structure.

A parser earns its place when the input has a language contract worth making explicit: commands should be composable, invalid input should be explainable, and changes should be testable without executing the application.

More parsers, fewer accidental languages.That does not mean inventing a DSL for every setting. Reuse JSON, TOML, an existing query language, or a domain parser when it fits. Reach for a grammar when your input really has syntax that those formats do not express well.
02 / The machinery

A lexer finds words.
A grammar finds relationships.

Textoriginal characters
Tokensnumbers, names, signs
Syntax treegroups & operators
Validationnames, units, rules
Applicationtyped operations

For 1+2*3, the lexer identifies five tokens. The parser groups them so that multiplication sits below addition in the tree. The tree records a relationship; evaluation is another operation.

Sly is a NuGet library. You describe lexical rules with attributes on an enum and grammar productions with attributes on C# methods. ParserBuilder reads that metadata and constructs the recognizer. Your methods are the typed actions called when a production matches.

You supplySly suppliesYou still own
Token patterns, symbols and modesThe lexer implementationWhich characters are legal in each context
BNF/EBNF production attributesGrammar construction and recognitionAmbiguity, acceptance boundaries and coverage
Typed production methodsDispatch into those methodsSyntax nodes and application semantics
Operator attributesGenerated expression rulesPrecedence, associativity and their tests

This is different from writing a recursive-descent parser by hand. It is also different from a Roslyn source generator: the ordinary Sly ParserBuilder path builds a parser from attributes in your .NET process. ANTLR’s normal tool instead emits source from a separate grammar before compilation.

The distinction matters operationally. A compact .NET application can use Sly without installing a Java generator. It still needs a defined grammar, runtime initialization, dependency management and qualification for its intended inputs.

03 / The annotated implementation

The interesting code is the language.

A small expression grammar can stay close to the C# that consumes it. Here are representative pieces from the downloadable laboratory.

01 · Token rules
internal enum ExprToken
{
    [Lexeme(@"[ \t\r\n]+", true)] Space = 1,
    [Lexeme(@"(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)(?:[eE][+-]?[0-9]+)?[A-Za-z]*")] Number,
    [Lexeme(@"[A-Za-z_@$][A-Za-z_0-9.$]*")] Name,
    [Lexeme(@"\+")] Plus,
    [Lexeme(@"\*")] Times
    // The complete source also declares grouping, calls and other operators.
}

The first rule skips whitespace. The number rule recognizes spelling, including engineering-style suffixes; it does not establish that a suffix is meaningful or that a value has the right unit. Those are semantic decisions.

02 · Operator rules and an AST action
[Operation((int)ExprToken.Plus,  Affix.InFix, Associativity.Left, 10)]
[Operation((int)ExprToken.Times, Affix.InFix, Associativity.Left, 20)]
public Node Binary(Node left, Token<ExprToken> op, Node right)
    => new(op.Value, left.Start, right.End, [left, right]);

Higher precedence makes multiplication bind more tightly in this definition. The method creates a node with two children and a physical source range. It does not multiply anything.

03 · Grouping is a production
[Operand]
[Production("group : Open ExprGrammar_expressions Close")]
public Node Group(Token<ExprToken> first, Node value, Token<ExprToken> last)
    => new("group", first.Position.Index, last.Position.Index + 1, [value]);

ExprGrammar_expressions is Sly’s generated expression-rule name for this class. The production says which token/nonterminal sequence matches. Its method says what syntax object to construct. A missing closing parenthesis is a grammar rejection before any evaluator or simulator is involved.

What is a “production,” exactly?

A production is one grammar rule: a name on the left and an allowed sequence on the right. In group : Open expression Close, a group consists of an opening token, an expression and a closing token. EBNF adds concise repetition and optionality: item+, item* and item?. Concise does not mean ambiguity disappears.

04 / The architectural boundary

Parsing should not turn things on.

A command may be syntactically valid while referring to a missing instrument. A circuit may parse while using an unsupported model. An expression may be well formed while referencing an unknown variable.

Keep these outcomes separate. A useful frontend produces located syntax. A binder resolves names. A validator checks the domain contract. Only a later application operation performs I/O, changes state, or asks a numerical solver to work.

Syntax asks

Is the differential pair closed? Are there two nodes? Does an expression have an operand after +? Is the control block terminated?

Semantics asks

Does the model exist? Does that port type match it? Are the units compatible? Is this command authorized? Can this analysis actually run?

The laboratory’s control test feeds a shell-looking command to the parser and checks that no marker file is created. Recognition retains command text; it does not execute it. That is evidence about this implementation path, not a general security sandbox or a guarantee about arbitrary semantic actions.

The reusable patternA UI, command palette, CLI and automation endpoint can share the same typed application operations. A text parser is an adapter into that system. It should not become a second, less-tested implementation of the application.
05 / Where the interesting work begins

The same character can change its job.

a1 in-node out/name gain
B1 out 0 V={v(in)-0.3}

In the first line, a hyphen or slash can belong to a node name. In the expression, those characters are operators. One globally permissive identifier regex can swallow subtraction; one globally arithmetic lexer can break legitimate node spellings.

Sly has built-in lexer modes. The generic-mode probe uses attributes such as these:

Enter and leave an expression context
[Mode("default")][Sugar("{")][Push("expression")] Begin,
[Mode("expression")][Sugar("}")][Pop] End,
[Mode("expression")][Sugar("-")] Minus

The executed probe tokenizes in-node {v(g)-1} out-node. Both hyphenated names remain intact outside the braces; the minus becomes an operator inside. This corrects an easy misconception: modes are not an ANTLR-only capability.

Important scope boundaryThe experiment has separate regex-based fragment grammars and a generic-lexer mode probe. It has not integrated them into one complete deck lexer. Showing that each mechanism works is not proof that the combined frontend is finished.

Source offsets are the durable anchor

A continuation can join a logical statement across physical lines and comments. The original characters should remain available for diagnostics, editing and reproducibility. Prefer absolute offsets into the original text over reconstructing source from normalized tokens.

a1 [first
* comment
+ second] model

In the measured Sly regex probe, second keeps the correct absolute UTF-16 index, 24 in the CRLF test string. Its reported zero-based line is 1, while the physical line is 2. The skipped multiline lexeme’s line accounting needs an adapter or a different lexical definition. Our ANTLR wrapper also uses a physical-position map for its own newline conventions.

That is useful engineering evidence. It is not a verdict that either library “cannot do locations.” It identifies where the integration boundary must do more work.

06 / A grammar earns its shape

The last name was not another port.

An XSPICE-shaped fragment ends in a model reference. Consider a1 in out gain: two named ports followed by the model gain. The straightforward first rule looked like this:

card : Name port+ Name

In the initial Sly implementation, the repeated port production consumed the final name. The test run had 14 passes and six failures. The current ANTLR grammar handles that shape with its recognition machinery; the candidate needed a more explicit boundary.

card : Name port tail
tail : Name tail?
tail : Number tail
tail : compound tail

The first port is required. For a named tail element, another tail makes this name a port; the final named element becomes the model reference. The C# action constructs the corresponding nodes. The library still recognizes the structure—there is no handwritten token-walking parser.

This named-model fragment is intentionally limited. The numeric-model-reference challenge exposes a missing production. A complete port grammar also needs typed vectors and other forms that are already covered by the simulator’s ANTLR frontend.

A terminator is not always a prefix

.control
.endc_extra
.endc

The generic control probe uses a sugar token for .endc. It rejects the example above, while the ANTLR baseline keeps the longer command name as a control record and recognizes the real terminator. The candidate needs a better token boundary rule.

These cases explain why parser work can be substantial even with a good library. The package removes the recognition engine you would otherwise write. You still have to define the language’s boundaries and test their consequences.

09 / Testing the claims
A green result is the beginning of an explanation.


The tests check malformed delimiters, missing operands, extra differential nodes, source offsets, precedence, lexical modes and inert control text. FsCheck adds 128 generated differential pairs with replay seed 551,20261031 and 128 malformed-string cases with 552,20261031. Malformed strings are bounded to 128 UTF-16 characters.


These are finite, reproducible property checks. They are not an exhaustive input search, a coverage-guided fuzz campaign, an adversarial-depth qualification or evidence that every SPICE dialect is supported.

A low aggregate can expose a scope mismatch: unit tests do not run the reporting CLI. A high API-class number still says little about whether the grammar recognizes every intended sentence. Attribute strings and third-party recognition behavior need their own acceptance evidence.


Mutation testing found a real weakness in the tests


The first focused Stryker.NET run on Trial.cs killed 12 mutants, with three survivors and four uncovered. Stronger lexical-diagnostic and failed-result assertions improved the final result to 15 killed, two survivors, two uncovered and three ignored.


The remaining survivors alter an error-list separator and a defensive failure-result null guard. The observed inputs do not distinguish them; that is not a general proof of equivalence. The two uncovered mutants concern construction failure of fixed valid grammars.


What was excluded from the mutation score?
The tool reported 79 compile-error mutants in the excluded CLI source and 148 ignored mutants in the excluded fixture/grammar files. These are not kills. The campaign did not mutate the third-party parser machine or grammar productions. The evidence preserves those distinctions instead of reporting a flattering combined score.


The downloadable lab’s parser and test source are the same implementation files, with a smaller dependency graph and a dedicated CLI. Its fresh test run also passed all 30 tests. The historical coverage and mutation figures above still describe the original study, not an invented measurement of the browser or a new full mutation campaign on this page.




10 / Does the complexity earn its place?
Choose the maintenance boundary you want.


ApproachGrammar lives inAttractive whenCost to keep visible
SlyC# enums, production and operator attributesA compact .NET DSL benefits from a typed, annotated definitionGrammar factoring, context integration, diagnostics and runtime construction
ANTLRSeparate grammar files; generated target-language sourceA substantial language, existing grammar or cross-language ecosystem fits the toolGenerator setup, grammar/target integration and version qualification
ParlotC# parser composition; generation facilities also existThe team likes composable C# parsing APIsExecutable grammar composition and the selected generation/runtime path
SuperpowerC# tokenizers and parser combinatorsExplicit tokenization and diagnostic-oriented composition fit the applicationMore of the language definition is assembled in C# code


This table describes approaches. It is not a speed benchmark, completeness ranking or proof that one package is universally easier to maintain. We executed the bounded Sly study; Parlot and Superpower are primary-source comparisons here.


Why we kept ANTLR


The simulator already has a working generated frontend, resource policies, source mapping, regression evidence and a complete declared-sample gate. Sly showed that a C# package is credible, not that replacing the current parser would buy enough benefit to justify requalification.


Java is needed for our pinned ANTLR generator, not for the generated C# parser at runtime. antlr-ng also provides a TypeScript-based generator with C# output. Changing generators would still need compatibility evidence; removing Java alone is not a behavioral qualification.


Sly is worth trying when…
You have a genuinely small language, a .NET team, clear examples and a desire to keep grammar rules close to typed syntax actions. Start with the hardest ambiguous and malformed inputs.
Skip the custom language when…
A standard format or complete existing parser meets the need. Do not create a new grammar simply because its annotations look elegant. Reuse should be tested against real inputs first.


The durable lesson is broader than a package choice: make textual boundaries explicit, preserve syntax independently of execution, and keep the evidence strong enough that a future engineer can change the language without guessing.




Reproduce / Actual tools required
Run the real parser on a new input.


The browser explorer is recorded evidence. To run Sly on arbitrary inputs, download and extract the source laboratory. It needs the .NET SDK pinned by its global.json (10.0.402 with latest-patch roll-forward) and first-time NuGet access.


PowerShell · from the extracted laboratory directory


$root = (Get-Location).Path
if (!(Test-Path -LiteralPath (Join-Path $root 'SlyTrial') -PathType Container)) {
    throw 'Run from extracted laboratory root'
}
$artifacts = $env:CODEX_ARTIFACT_ROOT

    throw 'Set CODEX_ARTIFACT_ROOT to an existing writable directory'
}
$artifacts = Join-Path $artifacts ('sly-lab-'+[guid]::NewGuid().ToString('N'))
if (!(Test-Path -LiteralPath $artifacts -PathType Container)) {
    New-Item -ItemType Directory -Path $artifacts | Out-Null

dotnet test ./SlyTrial.Tests --artifacts-path $artifacts -p:RestoreLockedMode=true
dotnet (Join-Path $artifacts 'bin/SlyTrial/debug/SlyTrial.dll') expression '1+2*3'


The CLI accepts expression, port or control, followed by a quoted fragment. Success returns exit code 0, rejected syntax returns 1 and invalid command-line arguments return 2. It prints syntax and diagnostics, never a simulation result. Package lock files travel with the source.


What this laboratory does not promise
No full-deck grammar, complete SPICE semantics, production-grade hostile-depth guard, NativeAOT qualification, Linux execution matrix or performance ranking. The study was executed on Windows/.NET. Sly’s MIT-licensed package is restored separately; no SDK, package cache, third-party binary or live service is embedded in this page.
