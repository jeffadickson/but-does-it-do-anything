01 / Why it matters

A checksum cannot explain a packet.

After yesterday's CRC++ deep dive, we know how to ask whether bytes were accidentally corrupted. Now ask: what do they mean? A C++ struct's raw memory includes ABI-defined padding and representation choices. It is not automatically a portable record format. When a RISCue actor posts an event or VeloSim replays a sequence, a byte-level contract has to identify field widths, order, endianness, and a version policy.

Good fit

Small, privately owned C++ binary protocols with explicit schema, predictable field types and an independently enforced capacity.

Less suitable

Long-lived, multi-language or externally published schemas that need discoverable fields, generated bindings and automatic migration tooling.

Finding in one sentencebitsery supports fixed-capacity contiguous output buffers and explicit serialized widths, but it does not promise checked writes beyond a non-resizable buffer, automatic heap freedom, CRC integrity, or automatic schema evolution.

02 / Mechanics

Write what you mean, not the struct's memory.

bitsery's documented serialize(S&, T&) function calls primitives such as value1b, value2b and value4b in a deliberate order. The default configuration uses little-endian representation and enables input adapter and data checks. A fixed std::array<uint8_t,N> can store output inline. Configuration source.

1–4Tick counter404 03 02 01

This nine-byte demonstration format is our example, not a standard bitsery message and not a deployed RISCue or VeloSim ABI. In a real protocol the application must also define units, reserved values, version handling, framing and corruption detection.

Input safety

The default reader returns an error and a full-consumption indication; both must be checked. Validate your own envelope version and length as well.

Output safety

Critical finding from the current OutputBufferAdapter: non-resizable overflow is guarded by assert, not a returned error. That assertion may vanish in Release.

Heap discipline

A fixed byte array does not allocate when initialized. A dynamic payload, extension or application helper still might. Audit the whole path.

Size preflight

For variable-length payloads, mathematically prove a worst-case bound or use a verified MeasureSize pass; never write first and hope.

05 / Reproducible source example

A complete C++20 golden-vector check.

Use the upstream public adapter and quick-helper APIs with a nine-byte std::array. The sample verifies explicit expected bytes, rather than relying solely on an encoder/decoder round-trip that could share the same mistake.

trace_demo.cpp · source-reviewed; not compiled against installed bitsery in this run
#include <array>
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <tuple>
#include <bitsery/bitsery.h>
#include <bitsery/adapter/buffer.h>
#include <bitsery/traits/array.h>

struct Trace {
  std::uint8_t version{};
  std::uint32_t tick{};
  std::uint16_t event{};
  std::uint8_t actor{};
  std::uint8_t flags{};
};

template<class S>
void serialize(S& s, Trace& t) {
  s.value1b(t.version);
  s.value4b(t.tick);
  s.value2b(t.event);
  s.value1b(t.actor);
  s.value1b(t.flags);
}

using Bytes = std::array<std::uint8_t, 9>;
using Out = bitsery::OutputBufferAdapter<Bytes>;
using In = bitsery::InputBufferAdapter<Bytes>;

int main() {
  constexpr std::size_t wire_size = 9;
  constexpr Bytes golden{
    0x01, 0x04, 0x03, 0x02, 0x01,
    0x34, 0x12, 0x07, 0xA5
  };
  static_assert(std::tuple_size_v<Bytes> == wire_size);

  Trace original{1, 0x01020304u, 0x1234u, 7, 0xA5u};
  Bytes wire{};
  const auto count =
      bitsery::quickSerialization<Out>(wire, original);
  if (count != wire_size || wire != golden) {
    std::cerr << "Golden-vector mismatch\n";
    return 1;
  }

  // Validate the application-owned envelope first.
  if (wire[0] != 1u || count != wire_size) return 2;

  Trace restored{};
  const auto result = bitsery::quickDeserialization<In>(
      {wire.begin(), count}, restored);
  if (result.first != bitsery::ReaderError::NoError ||
      !result.second || restored.version != 1u ||
      restored.tick != original.tick ||
      restored.event != original.event ||
      restored.actor != original.actor ||
      restored.flags != original.flags) {
    std::cerr << "Decode mismatch\n";
    return 3;
  }
  std::cout << "9-byte trace contract OK\n";
}
Do not generalize from a fixed nine-byte example.The 1+4+2+1+1 layout cannot exceed the provided nine-byte buffer, by construction. If you change this to strings or variable-length containers, a fixed output buffer's debug assertion is not sufficient Release-mode protection. Preflight or prove the maximum, check arithmetic, and test the actual library in your target build.

For true interoperability you must publish the versioned record contract, test unknown versions and length mismatches, and verify multiple compiler/target architectures. For resilient telemetry, combine with an integrity layer and framing as appropriate.

06 / Integration

Pin upstream in CMake; use Ninja to test.

Upstream CMake declares an interface target aliased as Bitsery::bitsery and declares version 5.2.5, with CMake 3.25 minimum. The SHA below is the observed upstream master revision (commit dated October 8, 2025); it avoids relying on a moving branch in the example. CMake source.

CMakeLists.txt
cmake_minimum_required(VERSION 3.25)
project(trace_packet LANGUAGES CXX)
include(FetchContent)
FetchContent_Declare(bitsery
  GIT_REPOSITORY https://github.com/fraillt/bitsery.git
  GIT_TAG 9bebfd4911b8ef52c5a67754ccb87a8fd5223414
)
FetchContent_MakeAvailable(bitsery)

add_executable(trace_demo trace_demo.cpp)
target_compile_features(trace_demo PRIVATE cxx_std_20)
target_link_libraries(trace_demo PRIVATE Bitsery::bitsery)

enable_testing()
add_test(NAME golden_trace COMMAND trace_demo)

cmake --build build --config Release

07 / Tradeoff matrix

Every promise has a boundary.

ConcernRiskRequired response
Output overflowNon-resizable adapter uses assert; Release may remove it.Prove or preflight capacity before any write; run sanitizers.
Unrecognized fieldsPacket contains no built-in schema identity.Version/envelope, golden vectors, explicit migration policy.
Corrupted packetAny payload bit may flip to another legal value.CRC for accidental error detection; authentication for hostile data.
Truncated inputPartial record or surplus bytes.Validate exact frame size, reader error and completion.
Unexpected allocationResizable vectors, extensions or application code allocate.Fixed members, allocator instrumentation, cold/steady tests.
Non-deterministic latencyMemory/cache effects and variable-length processing.Prove work bound and measure worst cases on target hardware.
Different runtimesC# consumers and foreign ABIs need exact byte contracts.Independent decoder and cross-language golden vectors.

Compared with earlier deep dives

nanopb offers schema/code-generated C messaging; zcbor supports CBOR/CDDL; CRC++ deals with accidental corruption but not layout. bitsery is most compelling when C++ producers and consumers deliberately share an optimized private binary contract. The comparison is architectural, not a measured speed ranking.

08 / Proposed project experiment

One small event record; real proof gates.

For RISCue, prototype a test-only binary event trace from a bounded queue. For VeloSim, prototype a versioned host replay packet and test repeatability, without replacing the existing normalized JSON structural schema or claiming that this fixes current producer–consumer mismatches. These are proposals, not verified integrations.

CheckAcceptance criterion
Golden vectors01 04 03 02 01 34 12 07 A5 on actual bitsery GCC/Clang/MSVC builds.
Malformed inputZero through eight bytes, wrong version and extra suffix rejected.
Capacity safetyVariable-length extension rejects insufficient buffer capacity before writing, in Release and Debug.
Heap behaviorInstrument allocator paths and demonstrate zero steady-state heap allocations.

Real-timeBounded execution and stack usage demonstrated on actual hardware; host throughput is not WCET.

RecommendationTry bitsery as an opt-in host trace format first. Adopt it for a real-time firmware path only after capacity, error, allocation and worst-case timing evidence exists. A compact packet is only useful if the recipient knows its contract.
