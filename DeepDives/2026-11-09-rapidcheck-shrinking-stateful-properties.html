01 / The verdict

RapidCheck is a good fit for host-side property tests of bounded queues, event routing, state-machine transition invariants, protocol codecs, and deterministic simulation. It is not a drop-in runtime library for allocation-free firmware. The harness itself uses dynamic data structures to generate, record, and shrink cases; the production component under test can remain allocation-free.

Generate Feed a property many inputs and command sequences rather than maintaining only hand-selected examples.
Shrink Remove irrelevant operations and simplify values to expose a smaller failing case.
Replay Capture a seed or the stronger opaque reproduce=… token for investigation and regression tests.
Where it belongs: Your C++20 desktop/CI test executable, linked to the same RISCue algorithms or portable abstractions used in firmware. Keep the RapidCheck dependency and generator heap allocations out of the flight/embedded binary.

02 / Generated properties, not a bag of assertions

A property states a rule that must hold for every valid input. RapidCheck chooses values, checks the rule, and, on falsification, attempts simplification. The upstream guide demonstrates this with reversing a list twice: the result must equal the original list. Its documentation describes generators, shrinking, and stateful commands. [1] [2]

  1. Write the invariant. For a fixed-capacity mailbox, a fourth push into a full capacity-three mailbox must be rejected without losing the first three messages.
  2. Generate valid input. Values may vary freely; longer scenarios can include push/pop commands. Constrain only what the interface actually requires.
  3. Run and compare. Check both return codes and observable state against an independent model.
  4. Minimize failure. Shrinking tries simpler cases and retains those that still fail; it does not mathematically guarantee a globally minimal counterexample.
  5. Replay and preserve. Capture the full failure text and a deterministic regression vector. A passing property campaign is evidence of sampled cases, not a proof of correctness.
Coverage is a design problem. An unconstrained generator might mostly produce empty/short queues and miss full-capacity behavior. Explicitly bias toward boundaries and classify the generated distribution. RapidCheck documents RC_CLASSIFY and RC_TAG for inspecting test categories. [3]

04 / A small, concrete C++20 property

The production-side example below uses only std::array, integer operations, and a caller-owned fixed-capacity object. No dynamic allocation is required by BoundedMailbox::push. RapidCheck surrounds that code in a host executable that supplies varying values. The property checks both overflow rejection and retention of prior data. A return value of nonzero on failure is important for CTest and CI. [1]

Scope of this property: It exercises one full-capacity boundary, not all dequeue, wraparound, concurrency, interrupt, or ordering behavior. This intentionally simple mailbox is not a full production ring-buffer implementation. A realistic RISCue campaign would add reference-model command sequences and stress reset/restart semantics.

05 / CMake, Ninja, pinning, and replay

RapidCheck is a compiled C++ library, not simply a standalone header. Its official CMake project exports the rapidcheck target. The upstream source currently has RC_ENABLE_TESTS and RC_ENABLE_EXAMPLES disabled by default; it also exposes RC_ENABLE_RTTI. The example below pins the reviewed upstream commit from 5 October 2026 rather than an unbounded moving branch. [4]

SituationRecommended record
Nightly exploratory testRecord randomly chosen seed and binary/commit hashes with failure output.
Developer reproductionRun with RC_PARAMS="seed=…"; on a failure, prefer the exact upstream-provided reproduce=… token.
CI regressionPin a seed and preserve the minimized commands as a deterministic standalone regression test.
Cross-platform evaluationRebuild with your intended GCC/Clang/MSVC toolchain, sanitizer selection, and exception/RTTI policy.

On Windows PowerShell, set the variable with $env:RC_PARAMS = 'seed=123456 max_success=1000' before invoking a test binary directly. In CMake, the ENVIRONMENT test property above is cross-platform. Official options include seed, max_success, max_size, max_discard_ratio, and noshrink; the reproduce token is generated upon failure. [5] [6]

06 / Stateful commands for RISCue and active objects

A single function property cannot exercise event-driven timing and lifecycle transitions. RapidCheck's rc::state API defines model, system under test, and commands with preconditions, updates, execution, and postconditions. Its official docs cover rc::state::check and command generators. [7]

RISCue mailbox Model push, pop, full, empty, cancellation, and queue ordering. Assert that the SUT's observable behavior matches the abstract model.
HSM / active object Generate event sequences such as Start → Tick → Stop → Start, then check legal transitions, entry/exit counters, and timer cancellation.
VeloSim Generate seed-fixed stimuli, compare independent models, and retain reduced mismatches as golden traces with toolchain metadata.

Crucial boundary: A host simulation of interleavings does not demonstrate thread safety or preemption correctness. Use separate stress, scheduler instrumentation, target hardware, sanitizers, and formal techniques for concurrency properties. If the generator allows impossible state transitions, it can drown the signal in discarded tests; preconditions should describe legitimate system states and not conceal bugs.

09 / A two-day qualification spike

Recommendation: Add one optional tests/property/ target in a host build, not to RISCue firmware. Keep the first experiment small and measurable:

  1. Build against the exact pinned RapidCheck revision using C++20 and Ninja on the intended host compiler(s). Verify the binary's success and failure exit codes.
  2. Wrap a fixed-capacity queue or HSM dispatcher with a fully independent reference model. Generate push/pop/reset sequences; explicitly favor empty/full/wraparound boundaries.
  3. Record seeds, minimize failures, and transform each discovered failure into a permanent deterministic regression case.
  4. Benchmark throughput (cases/second), memory peak, compile time, and diagnostic usefulness against existing handwritten tests and your Spice-style mutation campaigns.
  5. Only expand after you can demonstrate at least one useful failure or meaningful additional boundary coverage; skip the dependency if it adds compile complexity without benefit.
Decision criterion: One actionable, reduced counterexample that a small unit-test suite missed is more valuable than a thousand passes with weak generators. For requirement traceability, attach each property to a named interface invariant and retain the failure seed plus a human-readable minimized trace.
