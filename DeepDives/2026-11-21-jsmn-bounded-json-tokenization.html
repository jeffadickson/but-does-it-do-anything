What jsmn does—and what it does not

jsmn is a small C tokenizer for JSON-shaped input. It emits typed spans into the original caller-owned buffer instead of allocating object trees. Because the caller provisions its token array, it is a strong candidate for bounded control-plane parsing around an allocation-free embedded system. But a tokenizer is not an independently qualified JSON validator, and that distinction is the central engineering decision.

Official documentation describes a C89-compatible dependency-free single-header parser, tested on x86/amd64, ARM and AVR; those are upstream claims, not a RISCue qualification. The result type is a token list with OBJECT, ARRAY, STRING and PRIMITIVE categories. The codebase does not provide a complete schema system, JSON DOM, or numeric conversion API. Official source and README.

The memory-boundary diagram

The token structure contains type, inclusive start, exclusive end, and size. String offsets exclude surrounding quotes. An optional JSMN_PARENT_LINKS macro adds a parent index, changing the token layout; this setting must agree across compilation boundaries. As usual for zero-copy views, callers must keep the original buffer alive and immutable until conversion completes. A token is not a retained copy of its text.

The parser retains pos, toknext and toksuper. This enables incremental use, but the application must still bound the total frame, handle timeouts, reset/reinitialize parser state at frame boundaries, and prevent concurrent unsynchronized access. Source: upstream header.

Critical finding: strict mode is not strict validation

Security/assurance warning: JSMN_STRICT does not establish RFC 8259 conformance. The upstream tracker documents malformed JSON that is accepted despite strict mode. For untrusted, safety-relevant commands, never make jsmn the sole acceptance gate.

Issue #158 reports missing object separators and other invalid member syntax still being tokenized. Issue #247, reported December 21, 2025, demonstrates accepted leading/trailing commas and colons. Source inspection also shows that primitive token parsing classifies byte ranges without checking complete number or boolean grammar. true, false, integer overflow, surrogate-pair semantics, duplicate keys and trailing data require additional, explicit validation according to your protocol.

For a fixed engineering command shape, a narrowly specified canonical grammar can be checked before producing a typed event. For arbitrary third-party JSON, prefer a fully validating parser or independently qualified full grammar validation. The correct question is not merely “can I read this token?” but “can I prove this entire frame is valid for my accepted protocol?”

C++20: one deliberate, fail-closed schema

This illustrative decoder accepts exactly compact frames such as {"seq":42,"armed":false}. It intentionally rejects whitespace, reordered properties, escaped key names and extra properties. Its protocol is not general JSON. Using std::from_chars avoids locale-dependent parsing and produces an explicit overflow/error status. Output is assigned only after every check succeeds.

C++20 · Select to copy
#include "jsmn.h"
#include <array>
#include <charconv>
#include <climits>
#include <cstdint>
#include <string_view>

struct Command { std::uint32_t seq; bool armed; };

// Only {"seq":42,"armed":false}-style frames are allowed.
// Whitespace, key reordering and escaped names are forbidden.
[[nodiscard]] bool decode(std::string_view json,
                          Command& result) noexcept {
  if (json.empty() || json.size() > 128 || json.size() > INT_MAX)
    return false;

  std::array<jsmntok_t, 8> tokens{};
  jsmn_parser parser{};
  jsmn_init(&parser);
  const int count = jsmn_parse(&parser, json.data(), json.size(),
                               tokens.data(), tokens.size());
  if (count != 5 || tokens[0].type != JSMN_OBJECT ||
      tokens[0].start != 0 ||
      tokens[0].end != static_cast<int>(json.size()))
    return false;

  // Tokenization alone does not prove the JSON grammar.
  constexpr std::string_view prefix = "{\"seq\":";
  constexpr std::string_view middle = ",\"armed\":";
  if (!json.starts_with(prefix) || json.back() != '}')
    return false;
  const auto body = json.substr(prefix.size(),
                               json.size() - prefix.size() - 1);
  const auto separator = body.find(middle);
  if (separator == std::string_view::npos)
    return false;

  const auto number = body.substr(0, separator);
  const auto flag = body.substr(separator + middle.size());
  std::uint32_t seq{};
  const auto [end, ec] = std::from_chars(
      number.data(), number.data() + number.size(), seq);
  if (ec != std::errc{} || end != number.data() + number.size() ||
      number.empty() ||
      (number.size() > 1 && number.front() == '0'))
    return false;
  if (flag != "true" && flag != "false")
    return false;

  result = Command{seq, flag == "true"};
  return true;
}

The token count is checked (five tokens: root, two names, two values), the root must span the complete frame, and the canonical byte syntax is checked independently because tokenization cannot certify delimiters. The numeric conversion rejects overflow, partial consumption and leading-zero spellings; the boolean accepts only two literal byte sequences. The caller retains sole ownership of the input buffer and output object.

Verification scope: On November 21, 2026, the code above passed g++ 14.2.0 -std=c++20 -Wall -Wextra -Wpedantic -Werror -fsyntax-only using an API-compatible declaration stub. Network restrictions prevented downloading the upstream header into the compile environment; therefore this is a syntax-only check, not a real upstream compile, link or runtime test.

Reproducible CMake and Ninja integration

For embedded reproducibility, vendor jsmn.h plus the MIT notice at an exact reviewed commit. A separate C implementation unit avoids duplicate nonstatic symbols. Put #include "jsmn.h" in src/jsmn_impl.c. Then the target below builds the implementation once and makes JSMN_HEADER visible to consumers (declarations only). JSMN_STRICT is private to the actual implementation compilation, where it affects parser behavior.

CMake · Select to copy
# Vendor pinned upstream jsmn.h and LICENSE under third_party/jsmn.
# src/jsmn_impl.c contains: #include "jsmn.h"
add_library(jsmn STATIC src/jsmn_impl.c)
target_include_directories(jsmn PUBLIC third_party/jsmn)
target_compile_definitions(jsmn PRIVATE JSMN_STRICT=1)
target_compile_definitions(jsmn INTERFACE JSMN_HEADER=1)

add_executable(telemetry src/telemetry.cpp)
target_compile_features(telemetry PRIVATE cxx_std_20)
target_link_libraries(telemetry PRIVATE jsmn)

# cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
# cmake --build build --verbose

If using JSMN_PARENT_LINKS, define it consistently for both producer and all clients: it changes sizeof(jsmntok_t) and ABI. Alternatively use JSMN_STATIC for translation-unit-local header-only copies, while checking duplicate code size and unused-function warnings. The local command is cmake -S . -B build -G Ninja followed by cmake --build build, and target builds should use an explicit cross-toolchain file. Neither path was executed against upstream sources in this run.

Memory, timing and failure policy

Malformed contentToken errors INVAL or PART, plus schema checksReject; do not enqueue

WCETInput/token bound ≠ independently proven cycle boundAnalyze worst-case paths on actual target

Without parent links, the parser may scan backward through prior tokens when closing nested containers. Parent links can improve some traversal cases at a per-token memory cost. On common 32-bit integer/enumeration ABIs, the four-field token is often 16 bytes and the five-field variant often 20; measure with sizeof on every qualified target. A fixed array prevents heap allocation within jsmn, not within your logging, transport, callbacks or event queues.

Do not convert JSMN_ERROR_PART into unbounded buffering. An RTOS interface needs explicit frame length, maximum depth, timeout and backpressure behavior. Do not interpret a successful token count as proof that the entire input was a valid single JSON document.

RISCue, simulation and active-object applications

Proposed RISCue configuration ingress

Place a bounded, caller-owned frame buffer at the transport boundary. Tokenize and validate outside the hard-real-time active-object dispatch path; convert into a typed value event. Return separate fault codes for byte cap, token cap, malformed grammar, invalid schema and numeric range. Never retain a string_view into a DMA or network buffer whose lifetime expires after the parse call.

Proposed deterministic simulation replay

Normalize JSON into typed, timestamped events before writing trace fixtures. Record schema version, rejection reasons and conversion policy. JSON presentation order or whitespace must not become accidental simulator semantics. Jsmn does not supply deterministic scheduling or event ordering; those must be guaranteed by VeloSim or your scheduler design.

Proposed requirements and verification flow

Trace requirements such as INGRESS-BND-01 (byte cap), INGRESS-TOK-02 (token cap), INGRESS-VAL-03 (strict acceptance), INGRESS-NUM-04 (range), and INGRESS-RT-05 (bounded latency) into regression tests and target evidence. These IDs are proposed examples, not existing RISCue requirements.

Tradeoffs and alternatives

ApproachWhy consider itPrice paid
jsmnVery small, predictable token storage, offset-based zero-copy viewsApplication owns full grammar, schema, decoding and buffers
Custom canonical parserSmall and auditable grammar when protocol is fixedMore project code; only supports declared frame format
Full JSON parser/validatorProper arbitrary JSON syntax, often richer diagnosticsIndependently assess allocations, memory and exception policies
nanopb / zcborSchema-aware binary protocols (covered previously)Requires different wire format and integration

The decision hinge is trust. For a tightly controlled diagnostic channel with known canonical JSON frames, jsmn can be a helpful cheap scanner. For untrusted arbitrary JSON controlling a safety-relevant function, favor a validating parser or require a separately tested grammar gate. Neither “lightweight” nor “single header” establishes numerical, security, real-time or memory correctness by itself.

Qualification campaign: tests that actually matter

Run upstream tests, but do not stop there: published malformed-input issues mean passing the original suite is not sufficient to establish conformance. Introduce an independent JSON grammar oracle, differential fuzzing, and target measurements. Use the following as a seeded initial corpus and expand with property generation and minimization.

Adversarial corpus · Select to copy
Accept exactly these canonical examples:
{"seq":0,"armed":false}
{"seq":4294967295,"armed":true}

Reject:
{"seq":4294967296,"armed":false}   // overflow
{"seq":01,"armed":false}           // leading zero
{"seq":1,"armed":truE}             // bad literal
{"armed":false,"seq":1}            // wrong order
{"seq" :1,"armed":false}           // whitespace outside policy
{"seq":1,"armed":false,"x":0}      // unknown field
{"seq":1,"armed":false}{}          // extra root
{"seq":1,"armed":false             // truncated
{"a":}                             // malformed JSON; issue 158
:,:{},:,                           // issue 247
// Also fuzz invalid UTF-8, Unicode escapes, NUL, nesting,
// token exhaustion, duplicate keys and incremental resumes.
  1. Functional: accepted canonical frames, all invalid separators, duplicate/unknown fields, null handling, integer range and exact full-buffer consumption.
  2. Resource: byte lengths 0..129, tokens 0..9, max depth, no hidden allocator invocations, stack watermarks at O0/O2/LTO.
  3. State machine: repeated jsmn_init, partial frames, parser resumption, buffer replacement, timeout and task handoff.
  4. Robustness: ASan/UBSan on host, libFuzzer/AFL++ fuzzing, malformed UTF-8/escape cases, cross-check with strict RFC 8259 parser.
  5. Qualification: build on Linux and Windows x64 plus ARM target, measure cycles in worst observed configurations, document compiler/toolchain and exact library SHA; do not label empirical maxima as WCET proofs.

For code review, examine the three source-level configuration switches: JSMN_STRICT, JSMN_HEADER, and JSMN_PARENT_LINKS (plus linkage option JSMN_STATIC). A macro matrix is part of the contract.
