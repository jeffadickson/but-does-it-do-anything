Make overflow a design decision.

When a queue counter wraps from 250 + 10 into 4, the CPU did exactly what the type allowed. Boost.SafeNumerics helps make the mistake visible—before it quietly becomes a scheduling or telemetry defect.

01 / Executive decision

Catch the bug in a host model; keep the RTOS path proven and boring.

For RISCue, this library is most immediately useful as a reference oracle in host-side tests, not as an unchecked drop-in replacement for counters in a non-throwing ISR or scheduler path.

What it buys you

Checked arithmetic and narrowing, range-aware types, configurable result promotion, and policy-controlled error handling.

What it does not buy you

Automatic proof of WCET, hard-real-time behavior, zero allocation under the throwing policy, or freedom from application-level range mistakes.

Proposed experiment Independently implement a queue-admission predicate with no exceptions and compare its results against SafeNumerics across the uint8_t input domain. A test oracle is valuable even when the embedded build never links it.
02 / Mechanics

Three separate places an integer can go wrong

1. Arithmetic overflow

A signed integer overflow is undefined behavior in ordinary C++. For unsigned integers, modulo arithmetic is well-defined—but the wrapped result can violate a design requirement.

2. Narrowing conversion

Two uint8_t operands are generally promoted to int for addition. 250 + 10 evaluates to 260; assigning that to an 8-bit unsigned type yields 4.

3. Invalid state

A queue with capacity 64 cannot legitimately start with 65 occupied slots. No checked addition can repair a broken state invariant; validate the initial state separately.

What SafeNumerics adds

safe<T> checks operations and conversions; bounded safe_unsigned_range<MIN,MAX> encodes legal domains. Policies choose promotion and how an error is handled.

Important C++ subtlety uint8_t addition is not normally an eight-bit addition. The surprising defect is often the conversion back to eight bits, rather than overflow during the intermediate int expression.

04 / Explicit contracts

Pick a failure policy on purpose

FacilityBehavior / upsideEngineering boundary
safe<T>Checked integer arithmetic and conversions with default native promotionsDefault strict_exception_policy may throw std::system_error
safe_unsigned_range<0,N>Embeds a legal interval in the typeRuntime assignments outside that interval need a defined error policy
native promotionMatches standard C++ promotion rulesMay require checks on the result or its narrowing assignment
automatic promotionChooses wider result types when ranges permitNot unbounded arithmetic; changes types / C++ expression semantics
strict_trap_policyRejects at compile time operations that could failPotential errors cause compilation errors even if the current input data happens to be safe
ignore_exceptionPermits execution to continueDefeats the safety argument for a critical counter; not recommended

With trap policies, proving the range is often a type-level task. safe_signed_literal and bounded ranges communicate more to the compiler than a simple run-time variable. Consult the official policy and runtime-penalty chapters before treating a successful compile as an overall system proof.

05 / Executable reference

A tiny golden oracle and an allocation-free candidate

This standalone host program uses Boost.SafeNumerics to detect arithmetic narrowing and then checks the same cases with a narrow, constexpr, non-throwing predicate. The latter is the candidate for review in an embedded target. They serve different purposes.

bounded_queue_review.cpp

// bounded_queue_review.cpp — host-side experiment, C++20
// Tested with GCC 14.2 and Boost 1.83.0 (Linux x86-64).
#include <boost/safe_numerics/safe_integer.hpp>
#include <array>
#include <cassert>
#include <cstdint>
#include <iostream>
#include <system_error>

using SafeByte = boost::safe_numerics::safe<std::uint8_t>;

// Reference checker: catches narrowing from 260 to an 8-bit count.
// Host-side only: the default SafeNumerics policy throws on errors.
bool reference_admit(std::uint8_t used,
                     std::uint8_t incoming,
                     std::uint8_t capacity) {
    try {
        const SafeByte u{used};
        const SafeByte n{incoming};
        const SafeByte cap{capacity};
        if (u > cap) return false;  // Reject a corrupt starting state.
        const SafeByte total = u + n; // Checked conversion into 8 bits.
        return total <= cap;
    } catch (const std::system_error&) {
        return false;
    }
}

// Small target candidate: no exceptions, no allocation, no subtraction
// underflow. This function does NOT depend on SafeNumerics at runtime.
constexpr bool bounded_admit(std::uint8_t used,
                             std::uint8_t incoming,
                             std::uint8_t capacity) noexcept {
    return used <= capacity &&
           incoming <= static_cast<unsigned>(capacity) - used;
}

static_assert(bounded_admit(60, 4, 64));
static_assert(!bounded_admit(60, 8, 64));
static_assert(!bounded_admit(250, 10, 255));

struct Case {
    std::uint8_t used, incoming, capacity;
    bool expected;
};

int main() {
    constexpr std::array cases{
        Case{60, 4, 64, true},
        Case{60, 8, 64, false},
        Case{250, 10, 255, false},
        Case{65, 0, 64, false},
        Case{0, 0, 0, true},
        Case{0, 255, 255, true}
    };
    for (const auto& c : cases) {
        assert(reference_admit(c.used, c.incoming, c.capacity)
               == c.expected);
        assert(bounded_admit(c.used, c.incoming, c.capacity)
               == c.expected);
    }
    std::cout << "Six boundary cases agree.\n";
}
Proven algebra for the target predicate If used ≤ capacity, the subtraction capacity − used cannot be negative. Requiring incoming ≤ capacity − used is equivalent to used + incoming ≤ capacity without evaluating that addition. On an 8-bit domain, values are promoted before subtraction.

Actual local checks (17 November 2026): Compiled the equivalent reference and predicate with g++ 14.2 -std=c++20 -O2 -Wall -Wextra -Wconversion -pedantic and Boost 1.83. Ran all 16,777,216 possible triples as native-predicate inputs, 16,827 sampled comparisons against the SafeNumerics oracle, and separately tested six named boundary cases. Both the exploratory test harness and the copyable program subsequently compiled without warnings under those flags after explicit eight-bit conversions were added to test-loop call sites. The reference oracle was compared in 16,827 sampled cases; the bounded predicate was evaluated in every 8-bit input triple. The six named boundary cases and the CMake/CTest build also passed.

That is not exhaustive differential equivalence against SafeNumerics, nor a hardware timing test. It establishes a reproducible host correctness baseline, not WCET or allocator behavior for the library itself.

06 / Repeatable integration

CMake + Ninja without folklore

SafeNumerics consists of C++ headers but depends on additional Boost header modules. Pin a coherent Boost distribution with your package manager or toolchain image, rather than copying a single header out of the repository. The following uses the stable Boost::headers imported target.

CMakeLists.txt

cmake_minimum_required(VERSION 3.20)
project(bounded_queue_review LANGUAGES CXX)

# Lock the Boost release at the toolchain/package-manager level.
# Locally tested with Boost 1.83.0; newer versions need requalification.
find_package(Boost 1.83 REQUIRED)
add_executable(bounded_queue_review bounded_queue_review.cpp)
target_compile_features(bounded_queue_review PRIVATE cxx_std_20)
target_link_libraries(bounded_queue_review PRIVATE Boost::headers)

# cmake -S . -B build -G Ninja
# cmake --build build
enable_testing()
add_test(NAME queue_boundaries COMMAND bounded_queue_review)
# ctest --test-dir build --output-on-failure

Invoke cmake -S . -B build -G Ninja, cmake --build build, and ctest --test-dir build --output-on-failure. The CMake/Ninja configuration with Boost 1.83.0 was exercised locally. Newer versions and cross-compiled toolchains require their own validation.

Not an ISR recipe The host-side oracle deliberately uses exceptions. Do not copy reference_admit into a no-exceptions firmware image or assume that the default policy is allocation-free. The bounded_admit function uses only primitive integer operations, but still requires target-specific timing and requirements verification.

09 / Engineering exit criteria

Proof obligations before merging into RISCue

  1. REQ-QUEUE-001: Reject if used > capacity before calculating space.
  2. REQ-QUEUE-002: Accept exactly when incoming ≤ capacity − used and the starting state is valid.
  3. REQ-QUEUE-003: Test all 8-bit input triples, preferably against an independent integer-domain oracle.
  4. REQ-QUEUE-004: Compile the target predicate with exceptions disabled and enforce zero post-init allocations.
  5. REQ-QUEUE-005: Measure best / median / tail and WCET-oriented upper bounds on the actual target; median host benchmarks are insufficient.
  6. REQ-QUEUE-006: Record the exact Boost release, compiler version, flags, code size and commit in retained evidence.
  7. REQ-QUEUE-007: Test reentrancy/interrupt masks and queue synchronization separately: arithmetic correctness does not prove concurrency correctness.
Verdict: Qualified for exploration as a host-side numeric contract oracle; not qualified for RISCue real-time deployment by this study. The central win is to separate correctness policy from runtime implementation.
