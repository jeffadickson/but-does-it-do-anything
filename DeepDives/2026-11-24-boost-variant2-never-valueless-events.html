01 · The design problem

Consider a fixed-capacity mailbox shared by a scheduler and an active object. Its elements must carry several distinct payloads, but each element must retain exactly one meaningful type. A C union makes representation cheap; it also delegates lifetime and tag correctness to the programmer. A virtual base class permits open-ended polymorphism, but usually introduces indirection and lifetime management. A tagged union is a useful middle ground for closed event vocabularies.

Boost.Variant2, by Peter Dimov, is a header-only discriminated union introduced in Boost 1.71. It is broadly compatible with the C++17 std::variant interface, but deliberately changes the failure invariant. If replacement of a contained value throws, the previous value is retained rather than allowing a valueless variant. The library itself does not allocate storage for its alternatives on the heap. [1]

Decision: evaluate Variant2 for host-side simulation values and shared event definitions. For a strictly nonthrowing embedded event vocabulary, compare it directly with std::variant; the stronger exceptional-state invariant may add little if the project already excludes all throwing operations.

02 · What the invariant costs

The implementation selects an inline storage strategy according to the alternatives' move-construction properties. When it cannot rely on nonthrowing moves it may reserve a second storage region, allowing construction of the new object before the old object is destroyed. When moves cannot throw, a temporary can be constructed before replacing the original in its single storage region. [1]

Inspect Event::uses_double_storage() (available since Boost 1.83), sizeof(Event) and alignof(Event) at build time. A second buffer is not an exact 2× object-size promise, nor is single storage a promise of zero temporary stack usage. A large alternative increases every queue slot, including slots currently holding a tiny event.

For example, 128 slots of the measured 8-byte event occupy 1,024 bytes of element storage alone. Queue indices, alignment, synchronization and any enclosing metadata are additional. If one 256-byte diagnostic payload is inserted into the event union, remeasure every slot and the worst-case stack frame before accepting the change.

03 · C++20 lab: typed events

Use separate types even when fields share a representation. A timer generation is not interchangeable with an arbitrary status word. This original, standalone example demonstrates generation checking, exhaustive overloads and a reserved empty alternative. It is a minimal dispatch example, not a scheduler or HSM implementation. Save as event.cpp.

#include <boost/variant2/variant.hpp>
#include <cstdint>
#include <type_traits>
#include <cstdio>
namespace v2 = boost::variant2;
struct Start { std::uint32_t sequence; };
struct Timeout { std::uint32_t generation; };
struct Stop {};
using Event = v2::variant<v2::monostate, Start, Timeout, Stop>;
static_assert(std::is_trivially_copyable_v<Event>);
static_assert(!Event::uses_double_storage());
struct Controller {
    bool running = false;
    std::uint32_t generation = 0;
    void operator()(v2::monostate) noexcept {} // reserved empty slot
    void operator()(Start e) noexcept {
        generation = e.sequence; running = true;
    }
    void operator()(Timeout e) noexcept {
        if (running && e.generation == generation) running = false;
    }
    void operator()(Stop) noexcept { running = false; }
};
int main() {
    Controller c;
    Event e = Start{7}; v2::visit(c, e);
    if (!c.running) return 1;
    e = Timeout{6}; v2::visit(c, e);
    if (!c.running) return 2;
    e = Timeout{7}; v2::visit(c, e);
    if (c.running || e.valueless_by_exception()) return 3;
    e = Start{8}; v2::visit(c, e);
    e = Stop{}; v2::visit(c, e);
    if (c.running || v2::get_if<Start>(&e)) return 4;
    std::printf("Event size=%zu align=%zu double=%d\n", sizeof(Event), alignof(Event), int(Event::uses_double_storage()));
}

Notice that a stale timeout does not stop the active controller. Generation values must be allocated by a well-defined producer protocol; a 32-bit token eventually wraps, so prove that no stale event can survive until the same token is reused, or use a wider identifier and a reset protocol. The example does not implement that allocation policy.

Default construction selects the first alternative. Here monostate is explicitly chosen as an empty-slot marker; it should not be admitted as a real event. In production, separate queue occupancy from semantic event validity. Avoid generic catch-all visitors if a new event should force a compiler diagnostic at each consumer. Overloads should be exact and distinct.

04 · Fault injection: failed replacement

In a host model, a user-defined payload might fail during construction. This intentionally throwing test exercises the double-storage case and checks the old value, not merely the tag. Save as rollback.cpp. It belongs in the exception-enabled host test suite, not flight or RTOS hot-path code.

#include <boost/variant2/variant.hpp>
#include <cstdio>
#include <stdexcept>
namespace v2 = boost::variant2;
struct Fragile {
    explicit Fragile(int) { throw std::runtime_error("injected"); }
    Fragile(Fragile&&) noexcept(false) {}
};
using Value = v2::variant<int, Fragile>;
static_assert(Value::uses_double_storage());
int main() {
    Value v = 42;
    try { v.emplace<Fragile>(0); return 1; }
    catch (const std::runtime_error&) {
        auto p = v2::get_if<int>(&v);
        if (!p || *p != 42 || v.valueless_by_exception()) return 2;
    }
    std::printf("Value size=%zu align=%zu double=%d; rollback passed\n", sizeof(Value), alignof(Value), int(Value::uses_double_storage()));
}

The injected constructor never succeeds; the move constructor is declared potentially throwing to select the double-storage strategy. The test checks one failed emplacement only; it does not cover all assignments, self-aliasing cases or throwing visitor behavior. The container's value guarantee is not a transaction over external side effects: a constructor that writes a device register and then throws cannot be undone by Variant2.

05 · Access, ownership and error policy

OperationUseReview condition
visitTyped dispatchEvery alternative has a meaningful handler; handlers do not allocate or throw in strict paths.
get_if<T>Optional typed accessCheck null; pointer remains valid only while its contained object remains alive.
get<T>Access known alternativeWrong type raises bad_variant_access; avoid as an ordinary recoverable error path.
unsafe_get<I>Unchecked accessBan by default; requires established matching index.
index()Inspect active alternativeNever treat ordering of template alternatives as a permanent wire-format identifier.

A variant owns its selected value, but not necessarily resources referenced by that value. A payload with a raw pointer or span may borrow a producer buffer that has already been reused by the time the active object dequeues it. Prefer bounded value payloads or explicit pool handles with checked ownership transfer. The library's inline representation does not prevent alternatives from allocating memory, or callbacks from performing arbitrary work.

Use project-defined failure results for full queues, invalid messages or unexpected event types. An always-valid type is not an always-valid application state. A valid Start can still contain a stale sequence number. Validate admission before enqueue.

06 · CMake, Ninja and reproducible integration

Pin the complete Boost distribution, including transitive headers. The 1.83.0 upstream CMake target is Boost::variant2 and links Boost.Assert, Boost.Config and Boost.Mp11. [2] A distro package may provide the headers without a separate Variant2 CMake component. That occurred in this lab: asking for the component failed at configure time. The following tested fallback uses the installed aggregate Boost::headers target. On a full modular installation, prefer the explicit Variant2 target when available.

cmake_minimum_required(VERSION 3.20)
project(variant2_lab LANGUAGES CXX)
find_package(Boost 1.83.0 EXACT CONFIG REQUIRED)
enable_testing()
foreach(name IN ITEMS event rollback)
  add_executable(${name} ${name}.cpp)
  target_compile_features(${name} PRIVATE cxx_std_20)
  set_target_properties(${name} PROPERTIES CXX_EXTENSIONS OFF)
  target_link_libraries(${name} PRIVATE Boost::headers)
  add_test(NAME ${name} COMMAND ${name})
endforeach()
if(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
  target_compile_options(event PRIVATE -Wall -Wextra -Werror -fno-exceptions -fno-rtti)
  target_compile_options(rollback PRIVATE -Wall -Wextra -Werror)
endif()
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build -V

For WSL and Windows CI, provide an approved Boost installation through the package manager or an internally mirrored source archive with recorded SHA-256. Set CMAKE_PREFIX_PATH when needed. An exact CMake version constraint is a useful guard, not a substitute for pinning the archive, compiler, standard library, build options and dependency provenance. Keep host fault-injection and embedded exception-disabled targets separate; toolchain-specific flags require separate validation for MSVC and ARM targets.

08 · Where it fits (and does not)

Suggested RISCue use: typed mailbox entries with a fixed, compile-time vocabulary; protocol payloads represented as distinct types; explicit invalid/default admission. Use an existing bounded queue and a single owning active object. Variant2 does not provide atomic publication, queue capacity, ISR safety, memory barriers, priority scheduling or run-to-completion semantics.

Suggested VeloSim use: a typed event representation for scheduled stimulus, signal changes and timeout/control notifications. A deterministic scheduler must define a total ordering such as logical time, delta cycle, source ID and insertion sequence. Variant2 alone imposes no order. Record explicit event-kind identifiers and canonical field encoding; do not hash raw object representation (padding, ABI and tag layout may differ).

Suggested .NET analogy: the semantic model is a closed discriminated union. A C# value-type design with an explicit tag and bounded payload fields can express the same contract without relying on boxed interface payloads, but this is not a .NET library and no interop ABI is promised. Use explicit field serialization across languages and Native AOT boundaries.

Verified adoption: Boost.MySQL's 1.83.0 detail/field_impl.hpp stores its SQL field representation using boost::variant2::variant, including strings and binary blobs. [3] This is real upstream code use, not evidence that Boost.MySQL is allocation-free or that RISCue or VeloSim currently use Variant2. No external mission or safety certification was established.

09 · Alternatives and decision criteria

ChoiceAdvantageCost / limitation
std::variantStandard C++17/20 interface, no Boost dependencyCan become valueless in exceptional replacement cases; audit all alternatives and operations.
Boost.Variant2Retains an alternative after failed replacement; inline storagePossible second buffer; transitive headers; not full C++20 std::variant feature parity.
Manual enum + unionExplicit layout controlManual lifetimes, tags, copy/move, exception and visitor invariants.
Pool handle + kindSmall mailbox entries for large payloadsPool exhaustion, lifetime, ABA/stale-handle risks and indirection.

Decision gate: keep standard variants for the simplest no-throw event paths unless measurement or a shared invariant justifies the added dependency. For simulation/control objects that can fail during construction, the never-valueless property is particularly valuable. If a new alternative introduces double storage, treat that as a memory-budget design review rather than an incidental template change.

10 · Qualification and traceability

The following are proposed local requirements and tests, not existing project requirements or completed evidence.

Proposed IDRequirementEvidence needed
EVT-001Every admitted event belongs to one defined kind; empty marker rejected.Exhaustive admission tests; negative compile tests for missing visitor overloads.
EVT-002Mailbox slots stay within target RAM budget.Per-target static size/alignment assertions, map files; include queue overhead.
EVT-003No allocation or exception during dispatch after initialization.Intercept new/delete and C allocation hooks; inspect call graph; fault-test full queue.
EVT-004Failure to replace a host model value preserves its prior content.Throwing copy/move/construct matrix, all type pairs, sanitizer runs; check external side effects separately.
EVT-005Replay produces stable event order and canonical bytes.Cross-platform golden traces; stale timer, wrap and simultaneous-event tests.
EVT-006ISR or producer publication cannot expose partially constructed payloads.Queue synchronization proof and architecture-specific stress tests; not supplied by Variant2.

Benchmark identical event vocabularies across standard variant and Variant2, both small POD-like values and potentially throwing host types. Record maximum and distribution of dispatch latency, stack use, flash size, queue occupancy and compiler flags. Measure multi-variant visitation separately because the product of alternative counts can increase generated code. A host microbenchmark is not WCET evidence.

Review compiler-generated visitors and linker map for unexpected exception runtime dependencies on target. Add explicit compile-time checks for each alternative's trivial copyability or nonthrowing operations as required; even those traits cannot prove that a custom operation does not allocate. Use allocation hooks and target inspection as independent evidence.
