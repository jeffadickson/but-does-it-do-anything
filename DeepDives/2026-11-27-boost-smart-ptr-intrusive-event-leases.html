01 · Why intrusive ownership?

An active object posts a 128-byte immutable telemetry event to several consumers. Copying the payload for every recipient is simple and robust, but increases mailbox memory. Sharing a pointer can reduce copying; it can also silently introduce heap allocation or make reclamation nondeterministic. Boost.SmartPtr's intrusive_ptr<T> offers a third choice: shared ownership with reference-management hooks controlled by the application.

Unlike Boost.Intrusive containers (covered November 4), this is a lifetime mechanism, not a list or queue. It complements the bounded event pools covered November 1 and the typed event registry covered November 25. The selected library is Boost.SmartPtr, focusing exclusively on intrusive_ptr; the reviewed and compiled baseline is Boost 1.83.0, not the newest release.

Decision: Prefer value semantics for small events. Consider intrusive ownership only where bounded fan-out of larger immutable payloads measurably reduces memory or copying. A custom reference-count policy is required for a fixed pool.

02 · What the pointer actually does

The pointer stores an object address. Its constructors and destruction delegate ownership changes to free functions found through argument-dependent lookup (ADL). The object or an associated policy supplies the actual counter and reclamation behavior. The wrapper does not create a separate control block. See the versioned documentation [1] and header [2].

OperationOwnership effect
Construct from raw pointer (default)Acquire one additional reference if non-null.
CopyAcquire another reference.
MoveTransfer the held reference; source becomes null.
Reset / destructionRelease the old reference if present.
get()Borrow an address only; lifetime is not extended.
detach()Transfer ownership to a raw pointer; no release.
Construct with add_ref=falseAdopt a reference already acquired; no increment.

Critical trap: boost::intrusive_ref_counter, the convenient supplied helper, normally destroys the object using a delete expression at count zero [3]. It is not a ready-made static-pool policy. Its thread-safe counter option only addresses reference-count operations, not payload publication or pool synchronization. Do not inherit it for preconstructed array slots and assume it will recycle storage.

The public wrapper is flexible, not defensive: adopting without owning a reference, adopting the same reference twice, or constructing from a stale address defeats the ownership model. There is no built-in weak reference or generation validation. The application must specify these constraints.

03 · A two-slot, eight-owner contract

The example keeps two Event objects alive inside an array for the lifetime of a noncopyable pool. A slot with zero references is free. Admission sets the payload and count to one, and constructs a handle by adoption. When the final owner releases, the count returns to zero; the slot is reusable without running a destructor or releasing storage.

The two-slot scan is bounded by two inspections. Reference changes are fixed-size integer operations, and the cap of eight includes transient copies. Overflow or release at zero invokes a fail-stop policy (abort); ordinary pool exhaustion returns an empty handle. These are deliberately distinct error classes. A production system must choose a platform-specific invariant-failure policy and prove the maximum simultaneous owners, including temporary handles introduced by queue APIs.

Execution restriction: every acquisition, copy, destruction, observation and release occurs in one serialized execution context. No interrupt handler or other thread may access these slots. Payload reads are permitted only through a valid owning handle or a borrow whose duration is nested inside that ownership. The pool must outlive all owners. No user code may mutate a published payload, manually delete a slot, or manipulate the ADL hooks directly.

04 · Complete C++20 example

Save as main.cpp. The count starts at one before adoption; the custom add hook rejects attempts to create an owner of a currently free slot. Copy and move semantics then come from the actual Boost header. This sample is intentionally small enough to audit.

#include <boost/smart_ptr/intrusive_ptr.hpp>
#include <boost/version.hpp>
#include <array>
#include <cstdint>
#include <cstdlib>
#include <cstdio>
#include <utility>

namespace demo {
class Pool;
class Event final {
    friend class Pool;
    mutable unsigned refs_ = 0;
    std::uint32_t value_ = 0;
    Event() noexcept = default;
    Event(const Event&) = delete;
    Event& operator=(const Event&) = delete;
    friend void intrusive_ptr_add_ref(const Event* e) noexcept {
        if (e->refs_ == 0 || e->refs_ >= 8) std::abort();
        ++e->refs_;
    }
    friend void intrusive_ptr_release(const Event* e) noexcept {
        if (e->refs_ == 0) std::abort();
        --e->refs_;
    }
public:
    std::uint32_t value() const noexcept { return value_; }
};
using Handle = boost::intrusive_ptr<const Event>;
class Pool final {
    std::array<Event, 2> slots_{};
public:
    Pool() = default;
    Pool(const Pool&) = delete;
    Pool& operator=(const Pool&) = delete;
    ~Pool() { if (in_use() != 0) std::abort(); }
    Handle try_acquire(std::uint32_t v) noexcept {
        for (auto& e : slots_) {
            if (e.refs_ != 0) continue;
            e.value_ = v;
            e.refs_ = 1;
            return Handle(&e, false); // adopt exactly one existing ref
        }
        return {};
    }
    unsigned in_use() const noexcept {
        unsigned n = 0;
        for (const auto& e : slots_) n += e.refs_ != 0;
        return n;
    }
};
}

int main() {
    using namespace demo;
    unsigned checks = 0;
    const auto check = [&](bool b) {
        if (!b) std::abort();
        ++checks;
    };
    Pool pool;
    auto a = pool.try_acquire(42);
    check(a && a->value() == 42 && pool.in_use() == 1);
    auto fanout = a;
    check(fanout.get() == a.get());
    auto b = pool.try_acquire(99);
    check(b && b->value() == 99 && pool.in_use() == 2);
    check(!pool.try_acquire(7));
    const auto* address = a.get();
    a.reset();
    check(pool.in_use() == 2 && fanout->value() == 42);
    auto moved = std::move(fanout);
    check(!fanout && moved.get() == address);
    auto* token = moved.detach();
    check(!moved && token == address && pool.in_use() == 2);
    Handle adopted(token, false);
    check(adopted->value() == 42);
    adopted.reset();
    check(pool.in_use() == 1);
    auto reused = pool.try_acquire(7);
    check(reused.get() == address && reused->value() == 7);
    b.reset();
    reused.reset();
    check(pool.in_use() == 0);
    std::printf("%u checks passed; Boost %d; handle=%zu event=%zu pool=%zu bytes\n",
                checks, BOOST_VERSION, sizeof(Handle), sizeof(Event), sizeof(Pool));
}

The detached pointer demonstration models an ownership-transfer interface, not an encouraged production idiom. The intervening raw token still owns one reference. The saved address is compared only while the preconstructed pool storage remains alive; it is never dereferenced after its original event has been released. The reuse check illustrates why addresses cannot serve as persistent event identifiers. A production facade should hide raw construction, detach() and the adoption flag behind audited transfer functions; this example deliberately exposes the native API for teaching.

05 · Reproduce with CMake and Ninja

Use an installed Boost 1.83.0 development package exposing the Boost CMake config, a C++20-capable GCC or Clang, CMake 3.24+ and Ninja. No compiled SmartPtr library is linked in this example. Pin the dependency package or source archive and checksum in the actual toolchain manifest; the exact CMake version constraint alone does not ensure provenance.

cmake_minimum_required(VERSION 3.24)
project(intrusive_event_pool LANGUAGES CXX)
find_package(Boost 1.83.0 EXACT CONFIG REQUIRED)
add_executable(pool_demo main.cpp)
target_compile_features(pool_demo PRIVATE cxx_std_20)
set_target_properties(pool_demo PROPERTIES CXX_EXTENSIONS OFF)
target_link_libraries(pool_demo PRIVATE Boost::headers)
target_compile_options(pool_demo PRIVATE -Wall -Wextra -Wpedantic -Werror -fno-exceptions -fno-rtti)
enable_testing()
add_test(NAME pool_demo COMMAND pool_demo)
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
./build/pool_demo

The options are GNU/Clang-style; for MSVC provide compiler-specific options and validate the exception and RTTI configuration separately. The following sanitizer invocation was also executed on Linux:

g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror \
    -fno-exceptions -fno-rtti -O1 -g \
    -fsanitize=address,undefined -fno-omit-frame-pointer \
    main.cpp -o sanitized
./sanitized

For embedded cross-builds, set the board toolchain using CMake's toolchain file, omit host-only printf diagnostics from the firmware, and inspect link maps and target code generation. Avoid adding all Boost headers to a public firmware API; encapsulate the dependency in a small ownership adapter.

07 · Verified adoption versus proposed use

Actual use: Boost.Statechart's documented event interfaces accept intrusive pointers to const events [4]. The installed Boost 1.83 boost/statechart/event_base.hpp was inspected: its ADL functions delegate to event reference management and a deletion helper, and intrusive_from_this() returns a new intrusive owner when the event is reference counted or clones it otherwise [5]. This is direct source-level adoption by another library, not proof of bounded allocation or evidence of flight or automotive qualification.

Proposed RISCue integration: use an immutable event lease for a fan-out notification where a value copy demonstrably consumes more memory. Keep the scheduler-owned free pool separate from per-active-object mailbox storage. Each successful enqueue acquires or moves one owner; failed enqueue must preserve ownership or release the temporary. For all-or-nothing fan-out, reserve every mailbox before publishing; if reservations fail, abandon without partial delivery. If partial delivery is legal, record the exact recipients and error disposition.

Run-to-completion of one active object does not guarantee serialized access across active objects. If the scheduler supports preemption, the sample is not safe without a new synchronization design. Do not add atomics to the count alone and declare it safe: publication, acquire/reuse, last release, and pool lifetime need a complete protocol. An atomic decrement reaching zero must coordinate with reuse, potentially including synchronization with payload cleanup. ISR suitability requires target evidence, not a type name.

Proposed VeloSim integration: stable event sequence identifiers and logical publish/delivery/reclaim records, rather than logging raw addresses. Record pool exhaustion and per-recipient admission outcomes in the trace. A deterministic simulation may choose a deterministic free-slot ordering; it must not infer semantic identity from that implementation detail. For deferred state-machine events, bound how long an owner may retain a slot and account for deferral in peak occupancy.

Proposed .NET 10 integration: use a generated value-type token containing slot index and generation, backed by a fixed array or explicitly managed unmanaged arena. Copying a C# struct does not execute a retain hook: a direct struct translation of this RAII handle would allow double release. Prefer explicit lease operations and a generation-checked owner table, with a clear disposal protocol. Native AOT does not remove GC allocation or enforce linear ownership. This is a design suggestion, not a C# port or existing deployment.

08 · Alternatives and memory economics

ApproachAdvantagesLimitations
Value copy / typed variantIndependent lifetime, no shared count, simple local reasoningPayload copied for each recipient; mailbox slots sized for value type
Unique ownershipSingle release path; custom pool-return deleter possibleCannot simultaneously own across multiple recipients
Intrusive pointerInline object count, pointer-sized handle on measured host; policy-controlled reclamationObject modification, copy-side effects, cycles, no built-in weak owner
std::shared_ptrStandard ecosystem, weak references, independent control blockControl block generally needs storage; bounded allocator and reclamation policy require design
Index + generation leaseDetects many stale-handle uses; portable trace identity strategyGeneration wrap and explicit synchronization must be specified; ownership machinery must be implemented

Illustrative storage accounting: four mailboxes with eight queued 128-byte values each require 4,096 payload bytes. An alternative fixed pool of 32 events with 128-byte payload and a four-byte count needs 4,224 bytes before alignment, plus 256 bytes of 8-byte mailbox handles: worse in the worst case if all events are distinct. A 12-event pool would use 1,584 + 256 = 1,840 bytes, but only if the application can prove or explicitly accept that no more than 12 distinct events are concurrently retained. This comparison excludes queue metadata and alignment effects. Sharing is not a universal memory saving; model distinct in-flight payloads, queue capacity and fan-out.

Intrusive ownership also introduces a lifetime cost at the last release. In this simple sample the payload is a preconstructed scalar; a general pool containing resource-owning payloads would need deterministic destruction/reset and stronger exception/lifetime rules. Cyclic event ownership can keep slots occupied forever. Use immutable leaf payloads or acyclic ownership graphs.

09 · Requirements and qualification campaign

Suggested requirement identifiers below are proposals, not existing RISCue requirements or a certification claim. The sample is a feasibility spike; production use requires a traceable qualification campaign.

Extend the test suite with model-based property testing: represent each valid owner as a token in an independent ledger, generate valid operation sequences and compare counts and payload snapshots against the real implementation. Exercise move assignment between distinct and same-slot owners, copy assignment when temporary increment reaches the cap, repeated exhaustion, and pool destruction ordering. Fault tests must be isolated because the demonstrator deliberately aborts. Measure high-water counts including scheduler queues, deferred events, and instrumentation. A timing measurement is not a proof of WCET.

It provides no warranty or safety qualification. BSL-1.0 here means Boost Software License, not the similarly named Business Source License.

Record exact Boost version, package origin, archive hash, transitive header dependencies, compiler flags, approved targets, and any local patches. Keep Boost behind the adapter boundary so tests can compare alternative implementations. Review changes against the pinned upstream implementation before upgrading. The article code is original demonstration code; no upstream source listing was reproduced.

Recommendation: implement the serialized fixed-pool lease as an experimental adapter only after defining the mailbox fan-out contract and comparing against value-copy events. Prefer a smaller ownership surface than the public Boost pointer API. Do not use the provided default deleting reference-counter helper with static slots. Adopt the library if measured memory savings outweigh ownership complexity and target qualification succeeds.
