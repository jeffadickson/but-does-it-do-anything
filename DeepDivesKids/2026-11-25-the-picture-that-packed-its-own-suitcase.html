The Picture That Packed Its Own Suitcase!

Can a picture get smaller without losing a single colorful square? Meet a clever trick called run-length encoding.

1. Eight squares, two clues

Imagine sending your teammate a pixel-art picture of a hockey puck. You could call out every square: blue, blue, blue, blue, blue, blue, blue, blue. Or you could say “eight blues.” Both tell your teammate exactly what to draw!

A pixel is a tiny picture cell. A run is a streak of identical values next to each other in the chosen reading order. A computer can save each run as two numbers: how many and which color.

Before: 8 color clues

B B B B B B B B

After: 2 clues

8 B

That is run-length encoding (RLE). If decoding produces exactly the original values, it is lossless. The picture still has eight pixels. Only the instructions for rebuilding it got shorter.

Our toy format stores one byte per original pixel, or two bytes per run (count and color). It is not a real image-file format. We know the picture is 8 × 8 and share its palette, so we do not count headers, size or palette bytes.

3. Where the trick really appears

Documented: Windows bitmap images

Microsoft documents an RLE mode for indexed-color bitmaps. Its 8-bit mode can represent a repeated color with a count and color index, just like our big idea. It also includes literal data and special control codes, unlike our toy. [1]

Documented: medical image files

The DICOM medical imaging standard defines a lossless RLE format based on PackBits. The pydicom project shows how to encode a sample CT scan and save it as a compressed file. Its documentation also demonstrates an RGB example whose pixel data shrinks from 921,600 bytes to 424,152 bytes; those are example pixel-data sizes, not all file sizes. [2] [3] [4]

Documented: pictures from Mars (different compression)

JPL researchers studied how lossy compression affects the distance estimates made using pairs of Mars-rover pictures. Saving bandwidth can help, but too much image damage can make it harder to measure the terrain. Their ICER research is not our toy RLE algorithm. [5]

Imagined invention: suppose your own hockey scoreboard transmitted a pixel-art team logo to another rink using this lab's simple format. That is a design idea, not a claim about any actual rink or spacecraft.

4. Two-person paper mission

Materials: two sheets of paper, pencils, four colored pencils (or the letters W, B, Y, G), and a timer if you like.

  1. Both explorers draw a 4 × 4 grid. The artist makes a secret picture and numbers the cells in row order.
  2. Write the 16 color letters, then convert them to count/color pairs. Hide the original picture.
  3. The receiver draws a new picture using only those pairs. Check all 16 cells together. Count original and packed bytes using the toy rule.
  4. Switch jobs. Try a striped design and a highly mixed design. Predict which wins before counting.
  5. Bonus: change one count on purpose. Can your teammate spot the wrong number of cells? Can a bad color still make a picture of the right size?

Write down your observations: picture name, run count, original bytes, packed bytes, exact match yes/no. A real scientist keeps failed guesses, too!

Answer check: sixteen identical cells cost 2 toy bytes. Sixteen alternating letters in reading order cost 32 toy bytes. A decoder can check length but cannot detect every wrong color.

5. Code corner: meet the packer

This is the actual JavaScript encoder used by the lab. It visits each pixel once. If the last run has the same color and room for one more, increase its count; otherwise start a new run. A run can hold at most 255 pixels, because a count is one byte.

function encode(pixels) {
  const pairs=[];
  for (const pixel of pixels) {
    if (!Number.isInteger(pixel) || pixel<0 || pixel>3) throw new Error("Unknown pixel");
    const last=pairs[pairs.length-1];
    if (last && last[1]===pixel && last[0]<255) last[0]++;
    else pairs.push([1,pixel]);
  }
  return pairs;
}

Colors are numbered 0 through 3. Try calling encode([1,1,1,2,2,0]) in a browser console with the function above: it returns [[3,1],[2,2],[1,0]]. Notice that six input bytes become six packed bytes: no savings this time.

The decoder checks that each run has a valid count and color, and refuses to expand beyond the expected size. The lab compares the unpacked pixels with the original after every edit.

6. Why this matters on the ice and in Dad's workshop

Hockey replay detective

Imagine a goalie holding still while a puck flies past. Many background pixels might stay similar, but the puck moves quickly. Real video codecs can use more advanced tricks across time; they are not simply this pixel-run game.

Engineering detective

In a circuit simulator such as VeloSim, a signal may stay unchanged for many clock ticks. Imagine recording how long it stays the same instead of writing its value every tick. SharpHDL could describe a little digital counter that helps do this. MemForge is about managing computer memory carefully, so measuring the worst-case packed size is a useful connection. These are possible applications, not claims that Dad's projects already implement them.

Every trick has a price

RLE works best with long repeated values. It can make noisy pictures bigger. Compression and decompression take computation, file formats need metadata, and corrupt data may produce a wrong picture. A careful engineer tests the worst case, uses a size limit and chooses whether to store raw or packed data. Lossless compression protects information when decoding succeeds; it does not repair damaged messages like our earlier error-correcting-code lesson.

7. Suitcase champion quiz

1. What is a run?

A sequence of equal values that are adjacent in the chosen reading order.

2. What is the packed byte count of 12 blue pixels in a row?

Two bytes in the toy format: one count and one color.

3. What if six pixels all alternate between blue and yellow?

Six runs, 12 packed bytes, versus six original bytes. Leave it unpacked if your only goal is payload size.

4. Does lossless mean the picture has fewer pixels?

No. The instructions may be shorter; decoding must restore every pixel.

5. What does the word “lossy” mean?

Some original information may not be recoverable after decoding. It can save more space, but sometimes harms important details.

6. Why might Dad test the longest possible run and the worst possible picture?

To make sure a counter cannot overflow and that the computer has enough room even if compression grows the data.
