The mystery

How does a computer sing?

A piano has strings. A drum has a stretched skin. But a computer doesn't need strings or drums to play a tune!

When you press a piano key, something vibrates and makes the nearby air vibrate. Those vibrations travel to your ears as sound waves. A computer can calculate a wave as numbers, and your speakers turn the changing electrical signal into vibrations you can hear.

Think like a scientist: Will two notes at different pitches have the same wave pattern? Make a prediction before opening the experiment.

The science

Three secrets of sound waves

Pitch = wiggle speed

Faster vibrations make a higher note. Frequency is measured in hertz (Hz).

Loudness = wiggle size

Bigger changes in air pressure often mean louder sound. Keep volume comfortable!

Timbre = wiggle shape

Different shapes can change a sound's character, even at the same pitch.

For example, the musical note A4 is 440 Hz: its pattern repeats 440 times in one second. A different wave shape at the same 440 Hz can sound brighter or softer, even though the pitch stays A4.

Your laboratory notebook

Three experiments to try together

  1. High or low? Play C (262 Hz), then C↑ (523 Hz). About twice the frequency means one octave higher. Can you hear the relationship?
  2. Same note, different voice. Play A (440 Hz) with a sine wave. Change to square and play A again. The pitch stays the same, but how does the sound change?
  3. Build a soundtrack. Choose triangle, set a slow tempo, and press the melody button. Try fast instead. Which speed fits a rocket launch? Which fits a goalie making a dramatic save?
Bonus challenge: Draw a small wave and a tall wave on paper. Which would you expect to be louder? Does the shape alone tell you the exact sound? No: playback level and the speaker also matter.

Meet the library

What is Tone.js, really?

Tone.js is a free, open-source JavaScript library for making interactive music on websites.

Instead of having to build every sound from scratch, a programmer can ask Tone.js for a synthesizer, a drum-like sound, an effect, or a musical clock called a Transport. It uses the browser's native Web Audio tools underneath. Tone.js helps organize musical time and instruments; it is not a replacement for the speakers or the browser's audio engine.

Read actual code

Make Tone.js play a note

This is a practical Tone.js example adapted from the project's own README. It belongs in a JavaScript project after installing the library, not inside this offline page's built-in sound experiment.

// In a JavaScript project, first run: npm install tone
import * as Tone from "tone";

// Make a synthesizer and connect it to the speakers.
const synth = new Tone.Synth().toDestination();

// A button click unlocks sound in modern browsers.
document.querySelector("#play-c").addEventListener(
  "click",
  async () => {
    await Tone.start();
    synth.triggerAttackRelease("C4", "8n");
  }
);

To run this example: use an HTML button with id="play-c" and a bundler-based JavaScript project with the tone npm dependency. "C4" names a note; "8n" means an eighth-note duration. The button should be pressed by a person so the browser allows audio.

Change one thing: replace "C4" with "G4". What will happen to the pitch? Make your prediction before trying it in a Tone.js project.

Fact vs. invention

Where is this used? And what could we build?

✔ Published and documented

The Tone.js maintainers publish working synth examples, and their examples collection demonstrates musical programming techniques. Their showcase gallery lists projects such as Chrome Music Lab and Groove Pizza. The listing is evidence of a maintainer-curated showcase, not independent proof of a particular project's current runtime dependency.

💡 Our possible inventions

A hockey-goalie reaction game that beeps when the puck moves; musical feedback in an IceBreaker scoreboard; or a rocket simulator with a rising launch melody. These are ideas we could create—not claims that JPL, Dad's programs, or professional hockey already use Tone.js.

Connection to Dad's engineering: music needs timing, waves, and repeatable instructions. Those ideas also matter when simulating electronics, sending spacecraft data, or writing a game clock. But a web music library is not suitable by itself for deterministic spacecraft control or a real-time embedded operating system.

Engineer’s reality check

The tricky parts—and the permission slip

What it's good at: quickly trying musical ideas, organizing beats, making synthesizers, and teaching how sound can be programmed. It can save considerable audio-programming work.

What it is not: a recorded piano, an always-perfect timing system, or a replacement for specialized audio hardware. Browser autoplay rules mean sound normally needs a button press. Scheduling is precise inside the Web Audio engine, but the surrounding browser and operating system are not guaranteed hard real-time; devices may have audible latency. Fancy or sample-based instruments may also need audio files.

License: Tone.js uses the MIT license. In plain English: you may generally use and modify its code, including in commercial projects, as long as the required copyright and license notices remain included. That does not automatically grant rights to third-party recordings or songs.

Integration: install with npm install tone, import it in a web project, or use an appropriate browser distribution. The HTML page you are reading includes no outside fonts, scripts, sound files, or network requests; the playground uses standard browser APIs. A modern browser with Web Audio support and an audio-output device is needed for sound.

Safety: Start at a comfortable volume; never test with unusually loud sounds or put speakers near your ears. Adult help may be needed for npm installation or publishing projects online.

Reviewed for correctness

Native audio demonstration uses a user gesture, one reusable AudioContext, fresh oscillators per note, gain envelopes to reduce clicks, scheduled note timing, and an immediate stop control. The Tone.js snippet follows the official API with its npm/bundler prerequisite stated.

Reviewed for learning & access

Semantic headings and links, visible keyboard focus, descriptive labels, an aria-live status, responsive note buttons, no autoplay, no flashing animation, and no external assets. Source-backed examples and suggested inventions are clearly separated.
