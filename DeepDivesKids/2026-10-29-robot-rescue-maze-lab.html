Mission 01 • Briefing

A rover is stuck in a rocky canyon.

Imagine you are on Earth, sending a little robot across Mars. Its destination is a bright orange flag. But the direct route is blocked by rocks. How can a computer help?

🗺️

Make a map

Turn the landscape into a grid of squares. Some squares are safe. Some are blocked.

🌊

Send out a wave

Check the closest safe squares first, then squares farther away—like ripples in a pond.

🚩

Follow the clues

When the wave finds the flag, trace the path backward and give the rover directions.

That's a real computer science idea called breadth-first search (BFS). It sounds complicated, but you'll see every step in the playable maze below. On our map, every move goes up, down, left, or right; every move costs one step.

Our big question: Can the computer find the route with the fewest grid moves? Yes—under this game's simple rules. Real rovers face much trickier terrain.
Mission 02 • The secret

What is breadth-first search?

Pretend a team of explorers stands in one square. Everyone checks the square next door. Then the next ring. Then the next. Nobody skips ahead.

  1. Start at the rover.
    Put its square at the back of a queue (a waiting line).
  2. Explore in order.
    Take the first square from the line. Add each safe, unseen neighbor to the back.
  3. Stop at the flag.
    Each square remembers which square first led to it. Follow those memories back home.
Why is the route shortest? The search visits all squares one move away before the squares two moves away, and so on. The first time it reaches the flag, no route with fewer equal-length moves can exist. Stanford's computer-science teaching materials explain this same guarantee. [3]

Try saying it out loud: “First the nearest places, then the next-nearest places.” That's the whole big idea!

Mission 05 • Evidence check

Do real Mars rovers do this?

They do plan around obstacles—but our tiny game is not NASA's flight software. Here's what we can actually verify.

✅ Documented real work

NASA/JPL describes Perseverance's AutoNav system. The rover builds terrain maps using navigation cameras, judges whether possible routes are safe, and can re-plan around hazards. In a drive on July 15, 2023, it steered around a rock about 35 cm (14 in) tall. NASA published a visualization of that drive on September 21, 2023. [1]

NASA also published a computer simulation of a 2021 AutoNav drive. The simulation describes camera-derived height maps and routes rejected because of risks such as wheel drops or insufficient clearance. [2]

💡 Our invented classroom version

Our rover pretends the map is already known and perfectly flat. It cannot measure slopes, slippery sand, wheel clearance, or moving objects. We use BFS because it makes shortest-path search easy to see—not because NASA has said this exact little algorithm drives Perseverance.

Could a real engineer use a grid and a graph-search idea as part of a planning system? Absolutely. Does that prove the real rover uses our HTML code? No.

🧠 Engineering truth: A simulation is like a practice rink. It teaches important patterns, but you must test the real equipment before trusting it in a real mission.
Mission 06 • Hands-on

Try it without a computer

Make a paper version with a pencil, some small objects, and a partner.

  1. Draw a 7-by-7 grid on paper. Mark a starting square R and a different destination square F.
  2. Place pennies or small paper scraps on 10 squares to represent rocks. Leave the start and finish free.
  3. Write 0 in R. In every empty square touching a 0 (up, down, left, or right), write 1. Then fill the 2s, then 3s, and so on. Never write in rock squares.
  4. When you reach F, follow decreasing numbers back to R. Count the steps. You just acted as a search algorithm!
What if the numbers never reach F? There is no route using the allowed moves. You must remove a rock or change the destination. That is a valuable result, not a failed experiment.
Mission 07 • Code corner

The waiting-line trick, in JavaScript

The interactive game uses regular JavaScript included below in this HTML file. No library downloads, accounts, or external servers are required.

Here is the heart of the algorithm, simplified from the working demo. neighbors(here) is a helper that returns up to four squares; rocks contains blocked squares.

// The queue is a line: first in, first out.
const queue = [start];
const parent = new Map([[start, null]]);

for (let head = 0; head < queue.length; head++) {
  const here = queue[head];
  if (here === goal) break;

  for (const next of neighbors(here)) {
    if (!rocks.has(next) && !parent.has(next)) {
      parent.set(next, here); // Remember our clue!
      queue.push(next);       // Join the back of the line.
    }
  }
}
// Trace parent clues backward to make the route.

Notice head++: we move forward through the array instead of repeatedly removing the first item. That keeps this little program simple and avoids shifting every waiting item around.

Talk like a programmer: Queue = waiting line. Neighbor = a touching square. Parent = the square you came from. Algorithm = a repeatable set of instructions.

A tiny test to try

Choose Open plain in the lab. If the rover starts at column 2, row 8, and the flag is at column 12, row 2 (counting from 1), the shortest path has 16 moves: 10 right and 6 up, in any order. Run it and check.

Mission 08 • Engineering choices

What can go wrong?

Strengths and limitations of this maze and breadth-first search
IdeaWhat's greatWhat to watch out for
BFS on our gridFinds a route using the fewest equal-cost moves, if a route exists.It can check lots of squares and remembers a growing waiting line and parent links.
Four directionsEasy to understand and count.A rover can turn and drive at angles; diagonal distances and turning costs differ.
Known rocksEasy to replay and test.Real vehicles must discover obstacles and cope with uncertain sensor data.
Shortest in movesA clear, provable rule.Shortest is not necessarily safest, fastest, or easiest for wheels.
Browser animationFun to inspect or pause.Animation speed is not real rover speed or a computer benchmark.

On a graph, BFS uses time and memory proportional to the number of squares and connections it actually examines—often written O(V + E). You don't need to remember that formula today; just remember that a bigger maze usually means more work. [3]

Mission 10 • Check your thinking

Three quick questions

1. Why is the robot's waiting line important?

It makes the search check nearby squares before farther-away ones. That's what gives BFS its shortest-route guarantee when moves all cost the same.

2. The game reports 16 moves. Does that mean 16 meters?

No. A “move” means going into one neighboring square. We didn't give the squares a real-world size.

3. Why doesn't this simulation prove a real Mars rover is safe?

It ignores hills, loose soil, wheel sizes, slippery slopes, sensor errors, and many other real hazards. Real robots need much more testing.
