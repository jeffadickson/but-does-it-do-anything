01 • The mission

One rink. Thirty-five patches. One clever route.

Imagine that each square of our tiny rink is a patch of ice. Green means your imaginary cleaning robot visited it. White means a patch was missed. Gold shows where your robot stands. Your job: cover all 35 patches.

🎯 Coverage

Visit every patch at least once. Even one missed patch means unfinished work.

👣 Efficiency

Every move uses time and energy. Extra visits count as repeats.

🧭 Route planning

A rule like “go across, move down, come back” can be a tiny algorithm.

Important: the grid is a pretend robot puzzle, not instructions for driving a real ice resurfacer. A real machine turns in smooth arcs and works in overlapping passes.

02 • The secret

Why zigzags can be brilliant

Let's count carefully. The robot starts on one patch. Each move to a neighboring patch can add at most one new patch. So to visit 35 patches, the absolute minimum is 34 moves. There is no shortcut through that counting rule.

A serpentine route (also called a back-and-forth sweep) travels left to right on one row, drops down one square, then goes right to left on the next. Because it never needs to revisit a patch on this rectangular grid, it reaches 35 out of 35 in exactly 34 moves. That's a proof for this toy grid—not a promise about a real rink!

Two kinds of clever: getting everywhere is called coverage. Doing it with less extra travel is called optimization. Real engineering must also worry about obstacles, turning space, safety, and water.

05 • Hands-on, no screen

The marker-and-paper route test

  1. Draw a rectangle divided into 5 rows and 7 columns. Number the squares 1 to 35 lightly in pencil.
  2. Put a dot in the top-left corner square. Trace a path through edge-sharing squares using a washable marker.
  3. Try to visit all 35 squares without going through any square twice. Count your moves: a line from one square to a neighboring square is one move.
  4. Have a partner make a route with three detours. Compare the total moves. Can your partner find the repeats?
  5. Now draw a big pretend obstacle on one square. Can you still complete every unblocked square without repeating? (Sometimes you can't!)

Prediction: “I think my route will use ___ moves.” Observation: “It actually used ___ moves.” Explanation: “That happened because ___.”

Bonus challenge: On paper, put the robot in a different corner. Invent a route rule that still works. Explain it to someone who has never seen your picture.
06 • Code corner

An algorithm you can read aloud

A computer doesn't understand “be clever!” It understands exact instructions. Here's the same route-planning idea in plain JavaScript. It makes an array of row-and-column positions; it never drives a physical machine.

function snakeRoute(rows, cols) {
  const route = [];
  for (let row = 0; row < rows; row++) {
    for (let step = 0; step < cols; step++) {
      const col = row % 2 === 0
        ? step
        : cols - 1 - step;
      route.push([row, col]);
    }
  }
  return route;
}

const path = snakeRoute(5, 7);
// path contains 35 patches.
// Moving between them takes 34 moves.

Read the rule aloud: “For each row, go forward on even rows and backward on odd rows.” The percent sign (%) finds the remainder. An even row divided by 2 has remainder zero.

What about dad's engineering projects?

In VeloSim and other deterministic simulations, the same starting state and the same instructions should give the same result. Your imaginary robot follows that idea: it never rolls dice to decide where to go. In RISCue and state-machine projects, engineers also keep careful track of the system's current state—like which ice patch the robot is standing on. More advanced route problems resemble the optimization puzzles that Google OR-Tools can solve. Those are conceptual connections, not claims the projects already use our route planner.

Mini-quiz: What is the fewest moves for 35 patches if you start on one patch?

07 • Be a careful scientist

Where the model stops working

Real resurfacers are not chess pieces. They do not instantly turn 90 degrees inside one square; their blade width, turning radius, overlapping tracks, safe speed, water distribution, boards, and operator judgment matter. Our 34-move answer is only the theoretical minimum for this fictional grid.

The best route depends on the question. “Fewest tile moves,” “fewest sharp turns,” “shortest driving time,” and “smoothest real ice” may need different solutions. A plan that wins our puzzle might be a terrible way to operate a real machine.

Software tradeoffs: This page uses browser-native JavaScript; it needs no downloads, network requests, or external library. Google OR-Tools is an optional advanced tool for a parent or older student; it supports C++, Python, C#, and Java, but requires an installation and more complicated modeling. It uses the Apache License 2.0. Our simple route generator uses no OR-Tools code or third-party package, so no OR-Tools runtime or license bundle is needed to open this file offline.

Accessibility: Every tile is a labeled button, the route can be controlled by arrow keys or on-screen arrow buttons, progress is described in text, and updates are announced to screen readers. No sound or timed task is required.
