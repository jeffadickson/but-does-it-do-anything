A domain-specific language (DSL) gives a particular problem its own vocabulary. Adventure authors describe rooms and transitions; young programmers instruct a turtle; an application turns these sentences into predictable behavior.

Objectives: distinguish external from embedded DSLs; identify tokens, grammar, AST and interpreter; trace the history without attributing everything to Spring-era tooling; step through a program; recognize limitations and choose between manual parsing, parser combinators and grammar generators.

What runs here: the interactive adventure and turtle language are executed by a JavaScript interpreter in your browser. The companion C# source uses genuine Parlot and runs with a local .NET SDK. The current browser runtime does not contain the Parlot assembly, so this page does not claim to run Parlot in WebAssembly. See issue #9 for real browser-Parlot integration.

A long history, not a new trick

PeriodMilestoneLesson
1950s–1970sFORTRAN format controls, command shells, text processors, database query languages and compiler grammarsSmall specialized notations long predate the term's modern popularity.
1976–1977Colossal Cave Adventure by Will Crowther, expanded by Don WoodsCommands and authored world descriptions drive an interpreter.
1978Scott Adams's AdventurelandA compact game engine and reusable game data show the power of separating stories from machinery.
1979–1980Infocom founders develop Zork and the portable Z-machine approach; Infocom founded in 1979Story code and a virtual machine decouple authored content from hardware.
1979–1980sYacc, Lex, compiler generators, SQL and Unix tools spreadGrammars can be specified declaratively rather than entirely handwritten.
1990s–2000sParser combinators, PEGs, ANTLR and scripting-based DSLs matureEmbedding grammars or generating parsers reduces boilerplate, with tradeoffs.
2010s–2020sLanguage workbenches, language servers, Langium, tree-sitter, modern .NET libraries such as ParlotEditing tools, syntax trees, diagnostics and fast parsers improve the authoring experience.

Dates describe identifiable releases/publications, not the invention of the entire abstraction. Early dates differ by source and version; historical claims need stronger archival corroboration before a 1.0 release.

A DSL is more than a parser

Source text → tokens → grammar → commands/AST → interpreter → state → display
              (lex)     (parse)             (execute)

For a tiny DSL, line splitting can be enough. A parser library earns its keep with structured expressions, nesting, escaping, useful errors, and an extensible grammar. An editor needs even more: spans, completions, diagnostics, formatting and perhaps language-server features.

Parlot uses composable parsing functions in C# (Terms, And, Or, Then). Unlike a compiler generator requiring a separate grammar file, fluent parser combinators are ordinary C# expressions. Parlot's 2.x development also explores source generation; don't confuse development-branch capabilities with features guaranteed by the stable NuGet release.

Other options: hand-written recursive descent for a tiny stable grammar; ANTLR for a rich grammar and generated parser; Langium for a TypeScript language-service workflow; tree-sitter for incremental editor parsing. No single tool replaces the need to define semantics.

Build a three-room adventure

Syntax: LOOK, GO north|south|east|west, TAKE key, INVENTORY, SAY message, OPEN gate. This toy language uses one command per line and no quoted-string grammar.

Change the order: try opening the gate without the key, or going east before opening it. The program counter and world state update after each instruction.

A turtle robot that draws your code

Syntax: FORWARD n, BACK n, LEFT n, RIGHT n, PEN UP, PEN DOWN and REPEAT count command. Here LEFT/RIGHT rotate the robot; FORWARD/BACK move it. A full parser would permit nested blocks later.

Now implement the grammar with real C# and Parlot

The companion C# implementation is included in the source repository, with Parlot pinned to version 1.5.8. It demonstrates actual composable parsers and an AST-driven interpreter for both an adventure and a turtle. The standalone browser catalog publishes only app assets, so use this GitHub source directory to obtain and run it.

using Parlot.Fluent;
using static Parlot.Fluent.Parsers;

var direction = Terms.Text("north")
  .Or(Terms.Text("south"))
  .Or(Terms.Text("east"))
  .Or(Terms.Text("west"));

var go = Terms.Text("go")
  .AndSkip(Terms.WhiteSpace())
  .And(direction)
  .Then(x => new MoveCommand(x.Item2));

This example illustrates the API shape; the complete companion uses a straightforward grammar with explicit whitespace and tested commands. Run locally: dotnet run --project lessons/software-design/dsl-adventures/examples/ParlotDsl. SDK and NuGet restore are required.
