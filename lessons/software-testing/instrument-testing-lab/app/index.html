The problem

Our signal generator must be switched OFF before configuration, turned ON only after frequency and power are set, and turned OFF again after measurement—even when an HTTP calibration server fails. The corrected reading must survive a PostgreSQL round trip.

The first attempt checks only that the final reading equals −20.8 dBm. That seems reasonable, but it cannot detect an unsafe command order, an unhandled 503 response, or an INSERT statement that fails on a real database. We need different forms of evidence for different risks.

1 · xUnit

Runs tests and asserts outcomes with [Fact], [Theory], Assert, and asynchronous fixtures. It is the test framework—not a mock generator.

2 · NSubstitute

Programs stand-ins for our instrument interfaces; records calls; verifies order with Received.InOrder and counts with Received(1). It proves interactions, not real device behavior.

3 · WireMock.Net

Starts a real local HTTP listener, returns scripted JSON or errors, and records incoming requests. It tests URI creation, HTTP status handling, and response parsing.

4 · Testcontainers

Starts disposable PostgreSQL using Docker. It checks real schema creation, parameter binding, SQL execution, and retrieval—not mocked persistence.

Technical tutorial

1. The business invariant versus the interaction contract

Ordinary xUnit assertions prove the computed result and error paths. NSubstitute's ordered verification proves the generator is OFF before configuration. Crucially, Received.InOrder verifies an ordered subsequence; it does not guarantee that no additional dangerous SCPI commands were issued. For an exhaustive safety protocol use a stateful fake or compare a complete event journal.

Received.InOrder(() => {
    gen.WriteAsync("OUTP OFF", Arg.Any<CancellationToken>());
    gen.WriteAsync("FREQ 1000000", Arg.Any<CancellationToken>());
    gen.WriteAsync("POW -20 DBM", Arg.Any<CancellationToken>());
    gen.WriteAsync("OUTP ON", Arg.Any<CancellationToken>());
});

2. HTTP stubs are not substitute interface calls

With WireMock.Net, HttpClient sends a real loopback request. The server returns {"correctionDb":0.7} or HTTP 503. This catches errors a substitute ICalibrationClient cannot, but still does not validate the real production calibration service.

using var server = WireMockServer.Start();
server.Given(Request.Create().WithPath("/api/calibration").UsingGet())
  .RespondWith(Response.Create().WithStatusCode(503));

3. Why a real database matters

Mocks let you assert that SaveAsync was called. They cannot validate PostgreSQL syntax, parameter types, identity columns, or the actual stored value. Testcontainers provisions an isolated PostgreSQL container and supplies its connection string. Docker is mandatory only for this test category.

private readonly PostgreSqlContainer db =
    new PostgreSqlBuilder("postgres:16-alpine").Build();
await db.StartAsync();
await store.SaveAsync(reading);
Assert.Equal(-20.8, await ReadBackFromPostgreSql(), 8);

4. Reliability, safety, and limits

A finally block requests OUTP OFF after downstream failures. It cannot guarantee shutdown after power loss, process termination, a broken instrument interface, or a failed output-off command. The demo is not an approved flight-hardware or RF interlock implementation. The order assertion also does not prove HTTP and database chronology relative to SCPI calls.

5. How to run the real tests

From this lesson's checkout directory, run sh setup.sh setup (or ./setup.ps1 setup on Windows), then:

sh setup.sh test-unit  # xUnit + NSubstitute + WireMock.Net
sh setup.sh test       # includes real PostgreSQL via Docker
sh setup.sh preview    # browser lesson at http://localhost:8001

The toolchains and exact commands are documented in the lesson source directory. The source files are C# examples for local execution; the simulation on this page is not test results. The NuGet dependencies are explicitly versioned, while a fully validated locked restore is still an improvement to make.
